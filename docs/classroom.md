# 수업 연결과 교사 대시보드 (v0)

교사가 수업을 만들고, 학생이 코드로 참여하면 모둠별 진행 상황과 안전 경고를 한 화면에서 보고, 필요하면 모든 학생 화면을 잠시 멈출 수 있습니다. 사양은 `docs/specs/teacher-dashboard-v0.md`입니다.

수업 연결은 **선택 기능**입니다. 서버 주소가 없거나 연결이 끊겨도 학생 앱의 모든 실험은 그대로 동작합니다.

## 교사 PC에서 수업 서버 프로그램으로 하기 (가장 쉬운 방법)

교사용 **윈도우 PC**에 `SciBridgeON-수업서버.exe` 하나만 두면 됩니다. Node.js나 `pnpm`을 설치할 필요가 없습니다. 실행하면 수업 서버와 교사 화면이 함께 열리고, 같은 무선망에 있는 학생 기기(안드로이드 앱)가 이 PC로 수업에 참여합니다. 사양은 `docs/specs/teacher-local-server.md`입니다.

1. **내려받기.** GitHub 저장소의 Actions 탭에서 최근 실행(`CI`)을 열고, 맨 아래 **Artifacts**의 `windows-classroom-host`(90일 보관)를 내려받아 zip을 풉니다. 안에 `SciBridgeON-수업서버.exe`가 있습니다. 설치 프로그램은 없습니다. 이 파일을 교사 PC의 아무 폴더에 두고, 자주 쓰면 파일을 오른쪽 클릭해 「바로 가기 만들기」로 만든 바로 가기를 바탕화면에 둡니다.
   - 서명하지 않은 프로그램이라 처음 실행할 때 **Windows SmartScreen** 창("Windows의 PC 보호")이 뜰 수 있습니다. 「추가 정보」 → 「실행」을 누릅니다. 출처를 아는 파일(학교가 직접 내려받은 것)일 때만 하세요.
2. **실행.** exe를 두 번 누릅니다. 검은 창이 열리며 "수업 서버가 켜졌어요. 이 창을 닫으면 수업이 끝나요."가 나오고, 기본 브라우저에 교사 화면(`http://localhost:8787/`)이 열립니다. 8787번 포트가 쓰이고 있으면 8788~8799 가운데 빈 포트를 씁니다(창에 나온 주소를 따르세요).
3. **방화벽 허용.** 처음 실행하면 Windows 방화벽이 허용을 묻습니다. **「개인 네트워크」**를 체크하고 「액세스 허용」을 누릅니다(공용 네트워크는 필요 없습니다). 프로그램이 방화벽 규칙을 바꾸지는 않습니다. 허용하지 않으면 학생 기기가 연결되지 않습니다.
4. **학생 앱에 주소 입력.** 교사 화면 위쪽에 「학생 앱에 입력할 주소: 192.168.0.10:8787」과 QR 코드가 보입니다(검은 창에도 같은 주소가 나옵니다). 주소가 여럿이면 학생 기기와 같은 무선망의 주소를 고르세요. 교사 화면에서 「수업 만들기」를 누르고 6자리 코드를 칠판에 씁니다. 학생은 앱의 단원 목록에서 「수업 참여」를 눌러 맨 위 **「선생님 PC 주소」**에 이 주소를 쓰고, 수업 코드와 모둠 번호를 골라 「참여하기」를 누릅니다. 주소는 학생 기기가 기억해 다음부터 채워 줍니다. 주소는 `IP`만 써도 되고(포트는 8787로 봅니다), `IP:포트`, 또는 `ws://IP:포트/ws`도 됩니다.
5. **끝내기.** 교사 화면의 「수업 끝내기」 뒤에 검은 창을 닫으면 서버가 꺼집니다. 창을 닫으면 모든 수업이 사라집니다(수업 상태는 메모리에만 둡니다. 교사가 넣어 둔 튜터 모델 파일만 exe 옆 `tutor-models/` 폴더에 남습니다. 「튜터 모델 고르기」 참고).

참고
- **수업 만들기는 이 PC에서 연 교사 화면에서만** 됩니다(`localhost`로 연 화면). 같은 무선망의 다른 기기에서 교사 화면 주소를 열어도 수업을 만들 수 없고, 학생 참여와 수업 보기(열쇠 주소)만 됩니다. 학생 기기는 학생 앱으로 참여하세요.
- 주소 목록(`GET /host-info`)도 이 PC에서만 읽을 수 있습니다.
- 연결 주소는 교실 LAN용 `ws://`(암호화하지 않음)입니다. 학생이 보내는 것은 아래 「개인정보 원칙」의 진행 요약뿐입니다. 와이파이는 학교 무선망(학생이 아닌 사람이 접속할 수 없는 것)을 쓰세요.
- 개발자용: `pnpm host:build`가 교사 앱을 빌드하고 실행 파일을 `apps/classroom-host/dist/`에 만듭니다(Windows에서는 `.exe`, 리눅스에서는 `SciBridgeON-classroom-host`). `pnpm host:smoke`가 만든 파일을 실행해 교사 화면·`/host-info`·수업 만들기를 확인하고 끕니다. CI의 `windows-host` 작업이 Windows에서 같은 일을 하고 아티팩트를 올립니다. 환경 변수 `PORT`(포트 하나로 고정), `NO_BROWSER=1`(브라우저를 열지 않음), `TUTOR_MODEL_DIR`(튜터 모델 파일 폴더, 기본은 exe 옆 `tutor-models/`).
- 학교 서버·개발용 실행은 아래 「실행 방법」을 보세요.

## 실행 방법

### 1. 교실 노트북에서 (가장 간단)
```bash
pnpm install
pnpm classroom:dev     # 서버(8787)와 교사 앱(5175)을 함께 실행
pnpm dev               # 학생 앱 (5173), 다른 터미널에서
```
- 교사: `http://localhost:5175/` 에서 「수업 만들기」.
- 학생 기기가 같은 무선망에 있다면, 학생 앱을 열 때 서버가 있는 노트북의 주소를 알려 줍니다.
  `http://<노트북 주소>:5173/?classroom=ws://<노트북 주소>:8787/ws`
- 교사 앱도 노트북이 아닌 다른 기기에서 열 때는 `?classroom=ws://<노트북 주소>:8787/ws`를 붙입니다. 서버 주소를 정하지 않으면 교사 앱은 `ws://localhost:8787/ws`를 씁니다(개발용).
- 서버만, 또는 교사 앱만 실행하려면 `pnpm server:dev`, `pnpm teacher:dev`.

### 2. 학교 서버
- `pnpm --filter @sci/server start` 로 서버를 실행합니다(Node.js 22 이상). 환경 변수:
  - `PORT`(기본 8787), `HOST`(기본 0.0.0.0)
  - `ALLOWED_ORIGINS`: 접속을 허용할 화면 주소(쉼표 구분). 예: `https://class.example.kr,https://teacher.example.kr`. **비어 있으면 모두 허용**하며 시작할 때 경고를 남깁니다. 운영에서는 꼭 지정하세요.
  - `CREATE_SECRET`: 정하면 수업을 만들 때(교사 앱의 「수업 만들기」) 이 비밀번호가 필요합니다. 교사 앱이 「수업 만들기 비밀번호」 입력칸을 보여 주고, 주소에 `?key=<비밀번호>`를 붙이면 미리 채워 줍니다(주소 기록에 남으니 공용 기기에서는 입력칸을 쓰세요). 비우면 누구나 수업을 만들 수 있습니다. 서버를 인터넷에 열 때는 정해 두세요.
- 학생 앱과 교사 앱은 `pnpm build`로 만든 정적 파일(`apps/student/dist`, `apps/teacher/dist`)을 아무 웹 서버에나 올립니다. 서버 주소는 빌드할 때 `VITE_CLASSROOM_URL=wss://...`로 정합니다. 학생 앱의 주소 `?classroom=`는 **개발 서버이거나, 그 서버 주소의 호스트가 빌드 때 `VITE_CLASSROOM_ALLOWED_HOSTS`(쉼표 구분, 예: `class.example.kr`)에 있을 때만** 받습니다(링크 하나로 학생 기기를 엉뚱한 서버에 붙이는 일을 막기 위해서입니다). 교사 앱은 지금은 `?classroom=`를 그대로 받습니다.

### 3. 클라우드 (다음 단계)
로그인·학급 명부·기록 저장이 필요해지는 2단계에서 NestJS·PostgreSQL 기반 서버로 옮깁니다(`docs/DEVELOPMENT_PLAN.md` D9).

### HTTPS와 `wss://`
HTTPS로 제공하는 학생 화면은 암호화되지 않은 `ws://` 서버에 접속할 수 없습니다(Capacitor 앱(Android)은 앱 출처를 `http://localhost`로 두어 `ws://`에 접속할 수 있습니다. 근거는 `docs/app-packaging.md`). 이런 곳에서 쓰려면 서버를 TLS(`wss://`) 뒤에 두어야 합니다(역방향 프록시 등). 같은 건물의 `http://` 화면에서 시험할 때만 `ws://`를 씁니다.

## 수업 진행 순서
1. **교사가 수업을 만듭니다.** 교사 앱에서 「수업 만들기」를 누르면 6자리 수업 코드가 크게 나옵니다. 주소 끝(`#class=…&token=…`)에 수업 열쇠가 들어 있어 새로고침해도 같은 수업을 다시 봅니다. 이 주소는 다른 사람에게 보여 주지 마세요(열쇠를 가진 사람이 교사 권한을 갖습니다).
   - 안전 경고 소리를 쓰려면 시작 화면에서 「알림 소리 켜기」를 한 번 누릅니다(브라우저 정책상 첫 클릭 뒤에만 소리가 납니다).
2. **칠판에 코드를 씁니다.**
3. **학생이 참여합니다.** 단원 목록 위쪽의 「수업 참여」 → 수업 코드 6자와 모둠 번호(1~12)를 고릅니다. 이름이나 학번은 묻지 않습니다. 참여하면 「수업 ABC234 · 3모둠 · 연결됨」이 보이고, 새로고침해도 다시 참여합니다. 「수업 나가기」로 나올 수 있습니다.
4. **수업 중에는** 모둠 카드에서 단원, 단계, 시행 수, 최근 상황, 연결 상태를 봅니다.
   - 안전 경고가 생기면 위쪽 붉은 띠에 건수가 나오고, 해당 모둠 카드에 「확인」 버튼이 생깁니다. 교사가 확인해도 학생이 안전 경고 배너를 닫아야 실험 잠금이 풀립니다.
   - 「모두 멈춤」을 누르면 학생 화면 전체에 「선생님 말씀을 들어요 ✋」가 뜨고 입력이 막힙니다. 「다시 시작」으로 풉니다. 연결이 끊긴 기기는 멈추지 않습니다(교사가 확인할 수 없으므로).
5. **끝낼 때** 「수업 끝내기」(확인 단계가 있습니다). 모든 학생 연결이 끊기고 수업이 사라집니다.

## 튜터 질문 고치기
수업 전에 교사 앱에서 학생 화면의 튜터가 하는 질문을 고치거나 끄고, 새로 더할 수 있습니다. 단원 파일(매니페스트)의 기본 질문은 바뀌지 않고, 고친 내용만 따로(덧씌우기) 저장됩니다. 설계 근거는 `docs/specs/teacher-tutor-editor.md`입니다.

- **여는 법:** 교사 앱 첫 화면(수업 만들기 화면)과 수업 중 화면 위쪽의 「튜터 질문 고치기」를 누릅니다. 수업 없이도 열 수 있고, 수업 중에 열어도 수업(안전 경고 소리·붉은 띠 포함)은 계속됩니다. 단원, 활동(둘 이상일 때)을 고르면 질문이 상황별로 나옵니다.
- **할 수 있는 일:** 문장을 **고치기**, 그 상황에서 튜터가 말하지 않도록 **끄기**(학생 화면에 튜터 말풍선이 나오지 않습니다), **기본으로** 되돌리기, 아직 질문이 없는 상황에 질문 **더하기**(상황마다 질문 하나). 질문 안의 〔바꾼 조건〕 같은 칸은 학생 화면에서 실제 이름으로 바뀝니다. 그 활동의 기본 질문에 없는 칸은 쓸 수 없습니다. 위쪽에 「고친 질문 N개 · 끈 질문 N개 · 더한 질문 N개」가 보입니다.
- **검사 규칙(입력할 때마다):** 정답이나 학년에 맞지 않는 말(그 활동의 금지 구절·다루지 않는 개념), 120자·두 문장 초과, 물음표로 끝나는 질문 없음, 맞다·틀리다 판정 말, 전화번호·이메일, 쓸 수 없는 칸을 한국어로 알려 줍니다. **검사를 통과하지 못한 줄이 하나라도 있으면 「저장」을 누를 수 없습니다.** 기본 질문 그대로인 줄은 검사하지 않습니다. 학생 앱의 출력 가드는 이와 별개로 마지막 검사로 그대로 남습니다.
- **수업에 보내는 법:** 「저장」을 누르면 이 PC에 저장됩니다. 수업을 만들거나 다시 연결할 때, 그리고 수업 중 저장할 때마다(0.5초 묶음) 서버로 보내고, 서버가 참여한 모든 학생 기기에 전달합니다. 나중에 참여한 학생도 참여 직후에 받습니다. 수업 화면에 「튜터 질문: 고친 질문 N개를 학생 기기에 보냈어요」가 보입니다(고친 것이 없으면 숨김). 서버는 마지막 덧씌우기를 메모리에만 두고 수업이 끝나면 버립니다. 보낼 수 있는 것은 그 수업을 만든 교사 연결(또는 열쇠로 다시 연결한 화면)뿐이고, 학생이 보내면 `bad_message`입니다. 학생 기기는 받은 것을 **메모리에만** 두며(`sessionStorage`·`localStorage`에 쓰지 않음) 수업에서 나오거나 수업이 끝나면 지웁니다.
- **내보내기·불러오기:** 「파일로 내보내기」는 저장된 내용을 `튜터질문-YYYYMMDD.json`으로 내려받고, 「파일 불러오기」는 스키마와 검사를 통과한 줄만 편집 화면에 넣은 뒤 넣지 못한 줄 수와 이유를 보여 줍니다(「저장」을 눌러야 적용됩니다). 「모두 기본으로」는 확인을 거칩니다.
- **포트가 바뀔 때:** 덧씌우기는 교사 앱 주소(출처)별 브라우저 저장소(`localStorage`)에 있습니다. 수업 서버 프로그램의 포트가 바뀌거나(`PORT`) 다른 PC·다른 브라우저에서 열면 저장소가 달라져 고친 내용이 비어 보입니다. 그럴 때를 위해 수업 전에 「파일로 내보내기」로 보관해 두고 새 주소에서 「파일 불러오기」 → 「저장」으로 옮기세요.

## 튜터 모델 고르기
학생 기기에서 돌아갈 AI 튜터 예시 모델을 반(교사 PC)마다 하나 고릅니다. 지금은 **Qwen3 1.7B**(기본, 약 1.1 GB)와 **Qwen3 4B**(고사양 A등급 기기용, 약 2.5 GB) 두 모델이 후보입니다(4차 학습 결과).

- **여는 법:** 교사 앱 첫 화면과 수업 중 화면 위쪽의 「튜터 모델 고르기」를 누릅니다. 수업 중에 열어도 수업(안전 경고 포함)은 계속됩니다.
- **모델 카드:** 기기 저장 공간(4비트 기준 약 1.1 GB), 라이선스와 지켜야 할 점, 자동 검사 결과(규칙 통과율, 정답 누출, 엉뚱한 말 되풀이, 개인정보 되풀이, 영어 낱말 섞임, 한자·일본 글자)를 보여 줍니다. 「이 모델 쓰기」로 고릅니다.
- **답 견주어 보기:** 같은 실험 상황(교사·AI 견본, 학생 대화 아님)에 두 모델이 한 답을 나란히 봅니다. 기본은 이름을 가린 「답 A」「답 B」이고 문항마다 자리가 바뀝니다. 문항마다 「답 A가 더 나아요」「답 B가 더 나아요」「비슷해요」로 평가하면 모델 카드에 모델별로 셉니다. 단원, 문항 종류(일반 상황, 어려운 말), 자동 검사에 걸린 문항만, 아직 평가하지 않은 문항만으로 거를 수 있습니다.
- **모델 파일 넣기(수업 서버 PC에서 연 교사 화면에서만):** 모델 학습 결과(Kaggle)에서 받은 4비트 모델 파일(`.gguf`)을 교사 PC의 수업 서버에 넣어 두면, 같은 무선망의 학생 기기가 교사 PC에서 받아 갑니다(인터넷 서버는 쓰지 않고, 모델 파일은 앱에 넣지 않습니다). 두 가지 방법이 있습니다.
  1. **화면에서 넣기:** 「튜터 모델 고르기」에서 모델을 고른 뒤 「모델 파일 넣기」로 `.gguf` 파일을 고릅니다. 진행률이 보이고, 끝나면 파일의 `sha256`이 나옵니다. 모델이 아닌 파일(앞 4바이트가 `GGUF`가 아닌 것)이나 4 GB가 넘는 파일은 거절합니다. 이미 있는 모델에 다시 넣으면 새 파일로 바뀝니다.
  2. **폴더에 복사하기:** 수업 서버의 `tutor-models/` 폴더(exe와 같은 폴더, 시작할 때 검은 창에 경로가 나옵니다. 환경 변수 `TUTOR_MODEL_DIR`로 바꿀 수 있습니다)에 `qwen3-1.7b.gguf` 또는 `qwen3-4b.gguf`라는 이름으로 복사합니다. 서버가 켜질 때(또는 모델 고르기 화면을 열 때) `sha256`을 계산해 `.json`으로 적어 둡니다. 큰 파일은 계산에 시간이 걸립니다.
  - 「이 PC의 모델 파일」 목록에 모델별로 있는지, 크기, `sha256`이 보입니다. 고른 모델의 파일이 이 PC에 없으면 「이 PC에 모델 파일이 없어요」가 보이고 학생에게는 아무것도 알리지 않습니다.
- **학생 기기가 받는 것:** 고른 모델의 파일이 이 PC에 있으면 수업을 만들 때, 다시 연결할 때, 고른 모델이 바뀔 때마다 서버가 참여한 학생 기기(나중에 참여한 기기도)에 모델 이름·`sha256`·크기를 알립니다. 학생 기기는 **안드로이드 앱이고 기기 등급이 모델에 맞을 때만**(Qwen3 1.7B는 B등급 이상, Qwen3 4B는 A등급) 교사 PC에서 파일을 받습니다(같은 `sha256`의 파일이 이미 있으면 받지 않습니다). 웹 브라우저로 쓰는 학생 화면은 받지 않고 지금처럼 기본 질문을 씁니다. 학생 화면 위쪽 수업 상태 옆에 「튜터 모델 받는 중 42%」「튜터 모델 준비됨」「튜터 모델을 받지 못했어요. 수업은 그대로 할 수 있어요」가 작게 보이고, 교사 모둠 카드에도 「튜터 모델 받는 중」「튜터 모델 준비됨」「튜터 모델 오류」가 작게 보입니다(받는 일이 없는 기기는 표시가 없습니다). 받은 파일의 `sha256`이 다르면 지우고 오류로 봅니다.
- **교실 LAN에서 보이는 것:** `GET /tutor-models`(목록)와 `GET /tutor-models/<모델 id>.gguf`(파일, 이어 받기 지원)는 같은 무선망 누구나 읽을 수 있습니다(모델 파일에는 학생 정보가 없습니다). 파일을 **올리는 것**(`POST /tutor-models/<모델 id>`)은 이 PC(localhost)에서만 됩니다. 학교 서버 모드(`HOST_MODE` 없음)에는 이 경로가 없습니다.
- **비교 자료 만들기:** Kaggle 학습 노트북의 `summary.json`과 모델별 `eval-results.jsonl`로 `python3 ml/tutor/compare/build_compare.py`를 실행해 `apps/teacher/src/modelCompare.data.json`을 다시 만듭니다(사용법은 스크립트 첫머리).

## 개인정보 원칙
- **R2:** 학생은 수업 코드와 모둠 번호로만 참여합니다. 이름·학번은 받지 않습니다.
- **R3:** 학생 기기는 진행 요약만 보냅니다. 단원, 단계, 시행 수, 마지막 상황 종류, 예측과 결과가 달랐는지, 안전 경고 종류와 시각, 기기 등급입니다. **튜터 대화, 카메라 영상, 센서 원자료는 보내지 않습니다.** 서버는 규격에 없는 필드를 가진 메시지를 거절합니다.
- 학생 앱(APK)은 마지막에 쓴 「선생님 PC 주소」 문자열 하나만 기기의 `localStorage`(`sci-bridge.classroom-host.v1`)에 기억합니다. 학생 정보는 넣지 않습니다(탐구 기록장 `sci-bridge.logbook.v1`과 같은 곳이지만 내용이 다릅니다. `docs/app-packaging.md`).
- 튜터 질문 덧씌우기(`sci-bridge.tutor-edits.v1`)는 **교사 PC의 브라우저 `localStorage`에만** 있습니다. 질문 문장과 단원·활동 id뿐이고 학생 정보는 없습니다. 학생 기기에서는 서버가 보낸 것을 **메모리에만** 두고 어디에도 저장하지 않습니다. (학생이 서버로 보내는 내용은 위 R3 그대로입니다.)
- 고른 튜터 모델과 답 평가(`sci-bridge.tutor-model.v1`)도 **교사 PC의 브라우저 `localStorage`에만** 있습니다. 모델 이름과 견본 문항 id뿐이고 학생 정보는 없습니다.
- **R3 추가:** 학생 기기가 서버로 더 보내는 것은 status의 `model` 한 낱말(`none`·`downloading`·`ready`·`error`)뿐입니다. 튜터 입력·출력과 학생 말은 보내지 않습니다. 서버가 학생에게 보내는 `tutorModel`에는 모델 이름·`sha256`·크기만 있습니다.
- 서버는 수업 상태를 메모리에만 두고 DB를 쓰지 않습니다. 파일은 교사 PC의 모델 파일 폴더(`tutor-models/`)에 둔 모델 파일과 그 정보(`.json`)뿐이고, 학생 정보는 없습니다. 로그에는 수업 코드, 모둠 번호, 이벤트 종류만 남기고 메시지 내용은 남기지 않습니다.

## 서버 제한
수업당 모둠 12개, 서버당 수업 50개, 연결당 초당 메시지 10개, 메시지 8 KB(교사가 보내는 튜터 질문 덧씌우기 `tutor` 메시지만 48 KB까지). 연결이 하나도 없이 6시간이 지난 수업은 지워집니다.

리뷰 반영(v0.1)으로 더해진 제한:
- **교사 연결이 30분 동안 없으면** 학생이 남아 있어도 수업을 지웁니다.
- **멈춤 중 교사가 30초 동안 없으면** 서버가 멈춤을 풀고 학생에게 알립니다. 멈춤 막에는 「수업 나가기」 버튼도 있습니다.
- 같은 모둠 번호로 두 번째 연결이 오면 거절하되, 기존 연결이 **75초** 넘게 응답이 없으면 새 연결로 바꿉니다(ping은 30초마다).
- 30초 ping에 응답이 없는 소켓은 끊고, 10초 안에 만들기·보기·참여를 하지 못한 연결도 끊습니다.
- 열린 소켓은 서버 전체 600개, IP당 80개까지입니다(학교는 공용 IP 하나를 쓰므로 80으로 두었습니다). 초과 연결은 코드 1013으로 거절합니다. 서버를 역방향 프록시 뒤에 두면 IP가 프록시 주소로 보이므로 IP당 제한은 프록시 전체에 적용됩니다.
- IP당 수업 만들기는 시간당 10번입니다.
- 속도 제한(초당 10개)을 5초 동안 계속 넘기는 연결은 끊습니다.

## 알려진 한계
- 서버를 다시 켜면 수업이 사라집니다(메모리 상태). 교사 화면은 「이 수업을 찾을 수 없어요」를 보이고, 학생은 다시 참여해야 합니다.
- 로그인이 없습니다. 수업 열쇠 주소가 곧 교사 권한이고, 수업 코드를 아는 사람은 누구나 빈 모둠 번호로 참여할 수 있습니다.
- 기록 저장이 없습니다. 수업이 끝나면 현황은 남지 않습니다.
- 교사 화면의 「n분 전」은 서버 시계와 교사 기기 시계를 비교하므로 두 시계가 크게 다르면 어긋납니다.
- 실제 카메라 안전 감지 모델이 없어 안전 경고는 지금은 모의 감지기(`?dev=1`)에서만 생깁니다. 실제 감지기를 끼우면 같은 경로로 이어집니다.

- `HOST_MODE=1`: `pnpm --filter @sci/server start`를 교사 PC 모드로 켠다. 수업 만들기가 localhost에서 온 연결만 되고 `GET /host-info`를 연다. 학교 서버에서는 켜지 않는다(교사 PC 수업 서버 프로그램은 이 모드로 고정되어 있다).
- `CREATES_PER_HOUR`: IP 하나가 한 시간에 만들 수 있는 수업 수(기본 10). 학교 전체가 같은 공인 IP로 나가는데 교사가 많다면 늘린다. 테스트 서버는 1000으로 둔다.
