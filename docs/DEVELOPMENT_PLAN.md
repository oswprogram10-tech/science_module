# Sci-Bridge ON 개발 계획서

> 근거 문서: 「2022 개정 초등 과학과 교육과정 전 학년 단원 체계 및 국내외 실험 에듀테크·논문 분석 기반 차세대 과학 탐구 앱 개발 명세서」(21쪽)
> 작성일: 2026-11-03 · 상태: 초안 v0.1 (착수 전 검토용)

---

## 0. 요약

- **제품**: 초등 3~6학년 과학 32개 단원을 하나의 웹앱(PWA)에서 다루는 피지털(Phygital) 탐구 앱. 가상실험, 실물 센서, 온디바이스 비전, 소크라테스식 AI 튜터를 묶는다.
- **핵심 설계**: 32개 단원을 따로 만들지 않는다. **공통 런타임 1개 + 모달리티 엔진 5개 + 단원별 콘텐츠 매니페스트(JSON)** 구조로 만들고, 단원은 데이터로 추가한다.
- **일정**: 명세서의 3단계(1~6개월 / 7~12개월 / 13개월~)를 따르되, 앞에 **0단계(4주) 기술 검증**을 넣는다. 1단계는 단원 10개를 바로 만들지 않고 **대표 단원 3개로 수직 슬라이스**를 먼저 완성한 뒤 확장한다.
- **가장 큰 위험**: ① iPad(Safari)는 Web Bluetooth·Web Serial을 지원하지 않는다. ② 저사양 태블릿에서 브라우저 안 객체 탐지·자세 추정 성능. ③ 만 14세 미만 개인정보 + CSAP 환경에서 외부 LLM API를 쓰는 문제. 셋 다 0단계에서 결론을 낸다.

## 1. 명세서 검토 의견 (착수 전 정리할 것)

| # | 항목 | 문제 | 제안 |
|---|---|---|---|
| 1 | 단원 번호·이름 | 2022 개정 초등 과학 3~6학년 교과서는 검정 체제라 출판사마다 단원 이름·순서가 다를 수 있다. 명세서의 (1)~(16) 번호는 특정 구성을 전제한다. | 내부 키는 **성취기준 코드**(예: `6과03-01`)로 잡고, 단원명·순서는 출판사별 매핑 테이블로 둔다. 고시 원문(교육부 고시 제2022-33호)과 대조해 성취기준 목록을 확정한다. |

## 2. 범위 정의

### 2.1 MVP(1단계 말) 포함

- 공통 실험 런타임, 다중 표상 동기화 뷰어(거시·미시·기호 3분할)
- 탐구 게이트웨이(예측 → 가설·변인 매트릭스 → 실행 → 지연 피드백)
- 센서 브리지: BLE 온도센서 1종 이상, 마이크(Web Audio), 카메라, 모의(mock) 센서
- 비전: 안전 감시자(보안경 미착용, 가열기구 주변 장난 2~3개 시나리오부터), 지시약 색 판독기
- 소크라테스 AI 튜터(가드레일 포함) 텍스트 버전
- 교사 대시보드 최소 기능: 모둠 실시간 그리드, 안전 알림, 일시정지
- 우선 단원 10개

### 2.2 MVP 제외 (2단계 이후)

- VR/HMD, 학부모 대시보드, 오픈 배지·진로 포트폴리오, 생태 마을 게이미피케이션
- CASE/xAPI 국가 플랫폼 실연동, SSO (내부적으로는 처음부터 xAPI 형식으로 기록한다)
- 학생부 세특 초안 생성, 루브릭 생성기 등 교사용 생성형 도구

### 3.2 핵심 모듈 설계

**① 단원 매니페스트 (콘텐츠를 데이터로)**

```jsonc
{
  "id": "g5-solution",
  "standards": ["6과03-01", "6과03-02"],          // 성취기준 코드가 1차 키
  "caseGuid": "…",                               // CASE 매핑 (3단계)
  "engine": "matter",
  "experiments": [{
    "id": "dissolve-temp",
    "variables": {
      "candidates": ["waterAmount", "waterTemp", "soluteType", "stirSpeed"],
      "dependent": "dissolvedAmount"
    },
    "gateway": { "requirePrediction": true, "requireSingleIV": true, "mode": "open" },
    "views": ["macro", "micro:particles", "symbolic:line"],
    "sensors": [{ "kind": "temperature", "optional": true }, { "kind": "scale", "optional": true }],
    "safety": ["goggles", "hotplate"],
    "tutor": { "misconceptions": ["mc-dissolve-disappear"], "forbiddenAnswers": ["…"] },
    "limits": ["다루지 않는 용어 목록"]                // 교육과정 성취기준 해설의 제한점
  }]
}
```

**② 실험 런타임 + 타임라인 레코더**: 시뮬레이션 상태, 센서 샘플, 카메라 프레임 타임스탬프를 하나의 단조 시계에 기록한다. 그래프에서 한 점을 누르면 같은 시각의 영상 프레임과 미시 상태를 재생한다(명세서의 "변곡점 터치 → 동시 재생").

**③ 탐구 게이트웨이**: 실행 버튼은 다음 조건을 모두 만족해야 켜진다.
- 예측을 입력했다(그래프 스케치나 선택).
- 5~6학년 자율 모드라면 조작변인 1개, 나머지는 통제변인으로 분류했다.

조작변인을 2개 이상 바꾸고 실행하면 막지 않는다. 결과를 그대로 보여준 뒤 해석 단계에서 구조적 피드백을 준다(명세서 요구). 정오답 판정은 실험 사이클이 끝난 뒤에만 한다.

**④ 센서 브리지**: `SensorDriver` 인터페이스(`connect / stream / calibrate / disconnect`)를 두고, 모든 드라이버 위에 단위 변환·샘플링 레이트 정규화·끊김 재연결 계층을 얹는다. **Mock 드라이버를 1급 시민으로** 둔다. 센서가 없는 교실과 CI 테스트 둘 다 여기에 기대기 때문이다.

**⑤ 비전 워커**: 메인 스레드와 분리된 Web Worker에서 돌린다. 출력은 원본 영상이 아니라 **이벤트 메타데이터**(`{type:"NO_GOGGLES", groupId, ts, confidence}`)뿐이다. 기기 성능을 측정해 추론 주기(1~10fps)와 모델 크기를 자동으로 고른다.

**⑥ 튜터 게이트웨이**: 실험 상태 요약 → 시스템 프롬프트(단원별 오개념·금지 정답 포함) → LLM → **정답 누출 분류기**(규칙 + 소형 분류 모델) → 걸리면 재생성하거나 범용 탐침 질문으로 대체 → 로그. 클라이언트는 LLM을 직접 호출하지 않는다.

**⑦ 저사양 폴백 모드**: 기기 등급(A/B/C)을 자동 판정해 입자 수, 그림자, 비전 기능을 단계별로 끈다.

## 7. 품질·검증 전략

- **시뮬레이션 정확성**: 엔진마다 골든 테스트를 둔다(예: 온도 상승 시 용해량 단조 증가, 보일 법칙 PV≈상수 오차 5% 이내). 과학 교사·교수 자문으로 모델을 검수한다.
- **교육과정 준수**: 매니페스트의 `limits`(다루지 않는 용어·개념)를 튜터 출력과 UI 문구에 자동 검사한다. 예: 5학년 지층 단원에서 "습곡·단층", 3학년 동물 단원에서 "적응".
- **실기기 매트릭스**: 기준 기기 6종 이상에서 Playwright로 E2E를 돌리고, 센서는 하드웨어 인 더 루프 테스트 벤치를 둔다.
- **튜터 평가**: 단원별 평가셋(정답 유도, 탈옥, 부적절 콘텐츠, 학년 수준 어휘)을 CI에서 매 변경마다 회귀 검사한다.
- **접근성**: axe 자동 검사와 스크린리더 수동 점검을 함께 한다.
- **보안·개인정보**: 영상은 기기 밖으로 나가지 않고, xAPI Actor는 가명 ID를 쓰며, 튜터 로그는 보존 기한을 정해 자동 파기한다.
