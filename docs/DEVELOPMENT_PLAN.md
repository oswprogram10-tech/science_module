# Sci-Bridge ON 개발 계획서

> 근거 문서: 「2022 개정 초등 과학과 교육과정 전 학년 단원 체계 및 국내외 실험 에듀테크·논문 분석 기반 차세대 과학 탐구 앱 개발 명세서」(21쪽)
> 작성일: 2026-11-03 · 상태: v0.2 (주요 의사결정 반영)

---

## 0. 요약

- **제품**: 초등 3~6학년 과학 32개 단원을 하나의 앱에서 다루는 피지털(Phygital) 탐구 앱. 가상실험, 실물 센서, 온디바이스 비전, 소크라테스식 AI 튜터를 묶는다.
- **배포 형태**: 하나의 웹 코드베이스를 **Capacitor 네이티브 앱(iPadOS·Android)**으로 감싸 배포한다. 크롬북·Windows는 같은 코드를 PWA로 제공한다.
- **핵심 설계**: 32개 단원을 따로 만들지 않는다. **공통 런타임 1개 + 모달리티 엔진 5개 + 단원별 콘텐츠 매니페스트(JSON)** 구조로 만들고, 단원은 데이터로 추가한다.
- **AI 튜터**: 외부 LLM API를 쓰지 않는다. 직접 미세조정한 **소형 언어모델을 기기 안에서** 실행한다. 학생 대화는 기기 밖으로 나가지 않는다.
- **일정**: 명세서의 3단계(1~6개월 / 7~12개월 / 13개월~)를 따르되, 앞에 **0단계(4주) 기술 검증**을 넣는다. 1단계는 단원 10개를 바로 만들지 않고 **대표 단원 3개로 수직 슬라이스**를 먼저 완성한 뒤 확장한다.
- **남은 큰 위험**: ① 저사양 태블릿에서 비전 추론과 소형 언어모델을 함께 돌릴 수 있는가. ② 소형 모델의 한국어 품질과 정답 누출 억제. ③ 센서 제조사 프로토콜 확보. 셋 다 0단계에서 결론을 낸다.

## 2. 명세서 검토 의견 (원문, 결정은 §1)

| # | 항목 | 문제 | 제안 |
|---|---|---|---|
| 1 | 단원 번호·이름 | 2022 개정 초등 과학 3~6학년 교과서는 검정 체제라 출판사마다 단원 이름·순서가 다를 수 있다. 명세서의 (1)~(16) 번호는 특정 구성을 전제한다. | 내부 키는 **성취기준 코드**(예: `6과03-01`)로 잡고, 단원명·순서는 출판사별 매핑 테이블로 둔다. 고시 원문(교육부 고시 제2022-33호)과 대조해 성취기준 목록을 확정한다. |
| 2 | Web Bluetooth / Web Serial | iOS·iPadOS Safari는 둘 다 지원하지 않는다. 명세서는 iPad를 대상 기기에 포함하고 "설치 없는 웹앱"을 전제한다. | iPad에서는 **Capacitor 네이티브 셸**(BLE 플러그인)로 배포하거나 센서 기능을 제외한다. 0단계에서 결정. |
| 3 | 60fps 목표 | 렌더링 60fps와 비전 추론 속도가 한 문장에 섞여 있다. 저사양 기기에서 YOLO + 자세 추정을 60fps로 돌리기는 어렵다. | KPI를 나눈다: 시뮬레이션 렌더링 60fps(기준 기기), 비전 추론 **5~10fps 이상**, 안전 경고 지연 1초 이내. |
| 4 | WebGPU | 학교 보급형 크롬북·안드로이드 태블릿에서 WebGPU를 쓸 수 있다고 보장할 수 없다. | **WebGL 2.0을 기준선**으로 하고 WebGPU는 쓸 수 있을 때만 켠다. |
| 5 | AI 튜터 KPI "정답 노출률 0%" | 절대값은 측정·보증할 수 없다. | 단원별 레드팀 평가셋(정답 유도 프롬프트 500개 이상)에서 정답 직접 노출 0건 + 운영 로그 표본 감사로 정의한다. |
| 6 | CSAP vs 외부 LLM | CSAP 인증 국내 클라우드에서 운영하면서 해외 LLM API를 호출하면 학생 데이터가 국외로 나갈 수 있다. | LLM 게이트웨이에서 개인식별정보를 제거하고 실험 상태만 보낸다. CSAP 범위 안에서 쓸 수 있는 모델 경로를 법무 검토로 확정한다. |
| 7 | 1단계 우선 단원 수 | 본문은 혼합물의 분리를 포함해 11개, 로드맵 표는 "10개"다. | §7.2의 10개로 확정한다(혼합물의 분리는 2단계로). |
| 8 | 외부 기기 의존 | Science Cube WL100T 등 센서의 BLE GATT 프로토콜은 제조사 문서가 있어야 구현할 수 있다. | 0단계에 제조사 협조(SDK·프로토콜 문서)를 확보한다. 확보 못 하면 micro:bit·아두이노 기반 자체 센서로 대체한다. |
| 9 | 근거 수치 | 메타분석 수치(g=0.689 등)와 일부 출처(블로그·위키)는 검증되지 않았다. | 개발에는 영향이 없다. 제안서·사업계획서에 인용하기 전에 원문을 확인한다. |

## 3. 범위 정의

### 3.1 MVP(1단계 말) 포함

- 공통 실험 런타임, 다중 표상 동기화 뷰어(거시·미시·기호 3분할)
- 탐구 게이트웨이(예측 → 가설·변인 매트릭스 → 실행 → 지연 피드백)
- 센서 브리지: BLE 온도센서 1종 이상, 마이크(Web Audio), 카메라, 모의(mock) 센서
- 비전: 안전 감시자(보안경 미착용, 가열기구 주변 장난 2~3개 시나리오부터), 지시약 색 판독기
- 소크라테스 AI 튜터: 규칙 기반 탐침 질문 엔진 + 기기 내 소형 모델 v0(우선 단원 3개 학습), 가드레일 포함
- iPadOS·Android 앱(Capacitor) 내부 배포, 크롬북 PWA
- 교사 대시보드 최소 기능: 모둠 실시간 그리드, 안전 알림, 일시정지
- 우선 단원 10개

### 3.2 MVP 제외 (2단계 이후)

- VR/HMD, 학부모 대시보드, 오픈 배지·진로 포트폴리오, 생태 마을 게이미피케이션
- CASE/xAPI 국가 플랫폼 실연동, SSO (내부적으로는 처음부터 xAPI 형식으로 기록한다)
- 학생부 세특 초안 생성, 루브릭 생성기 등 교사용 생성형 도구

### 4.2 핵심 모듈 설계

**① 단원 매니페스트 (콘텐츠를 데이터로)**

```jsonc
{
  "id": "g5-solution",
  "standards": ["6과03-01", "6과03-02"],          // 성취기준 코드가 1차 키
  "caseGuid": "…",                               // CASE 매핑 (3단계)
  "engine": "matter",
  "experiments": [{
    "id": "dissolve-temp",
    "variables": {
      "candidates": ["waterAmount", "waterTemp", "soluteType", "stirSpeed"],
      "dependent": "dissolvedAmount"
    },
    "gateway": { "requirePrediction": true, "requireSingleIV": true, "mode": "open" },
    "views": ["macro", "micro:particles", "symbolic:line"],
    "sensors": [{ "kind": "temperature", "optional": true }, { "kind": "scale", "optional": true }],
    "safety": ["goggles", "hotplate"],
    "tutor": { "misconceptions": ["mc-dissolve-disappear"], "forbiddenAnswers": ["…"] },
    "limits": ["다루지 않는 용어 목록"]                // 교육과정 성취기준 해설의 제한점
  }]
}
```

**② 실험 런타임 + 타임라인 레코더**: 시뮬레이션 상태, 센서 샘플, 카메라 프레임 타임스탬프를 하나의 단조 시계에 기록한다. 그래프에서 한 점을 누르면 같은 시각의 영상 프레임과 미시 상태를 재생한다(명세서의 "변곡점 터치 → 동시 재생").

**③ 탐구 게이트웨이**: 실행 버튼은 다음 조건을 모두 만족해야 켜진다.
- 예측을 입력했다(그래프 스케치나 선택).
- 5~6학년 자율 모드라면 조작변인 1개, 나머지는 통제변인으로 분류했다.

조작변인을 2개 이상 바꾸고 실행하면 막지 않는다. 결과를 그대로 보여준 뒤 해석 단계에서 구조적 피드백을 준다(명세서 요구). 정오답 판정은 실험 사이클이 끝난 뒤에만 한다.

**④ 센서 브리지**: `SensorDriver` 인터페이스(`connect / stream / calibrate / disconnect`)를 두고, 모든 드라이버 위에 단위 변환·샘플링 레이트 정규화·끊김 재연결 계층을 얹는다. **Mock 드라이버를 1급 시민으로** 둔다. 센서가 없는 교실과 CI 테스트 둘 다 여기에 기대기 때문이다.

**⑤ 비전 워커**: 메인 스레드와 분리된 Web Worker에서 돌린다. 출력은 원본 영상이 아니라 **이벤트 메타데이터**(`{type:"NO_GOGGLES", groupId, ts, confidence}`)뿐이다. 기기 성능을 측정해 추론 주기(1~10fps)와 모델 크기를 자동으로 고른다.

**⑥ 온디바이스 튜터**: 실험 상태 요약 + 학생 발화 → 기기 내 소형 모델 → **정답 누출 검사**(규칙 + 소형 분류기) → 걸리면 재생성하거나 규칙 기반 탐침 질문으로 대체. 서버로는 집계만 보낸다. 상세는 §6.

**⑦ 저사양 폴백 모드**: 기기 등급(A/B/C)을 자동 판정해 입자 수, 그림자, 비전 기능, 튜터 모델 크기를 단계별로 낮춘다. 비전과 튜터 모델은 동시에 메모리에 올리지 않도록 스케줄링한다.

## 6. 온디바이스 AI 튜터 모델 (D3)

### 6.1 요구사항

- 기기 안에서만 추론한다. 학생 발화와 실험 상태는 기기 밖으로 나가지 않는다.
- 하는 일은 좁다. 구조화된 실험 상태와 학생 발화를 받아 **초등 수준 한국어 탐침 질문 1~2문장**을 만든다. 범용 대화는 하지 않는다.
- 결론, 정답, 보고서 문장을 직접 만들지 않는다. 목표 노출률은 0%(D4).
- 성능 목표(기준 기기, 0단계에 확정): 첫 토큰 1초 이내, 초당 8토큰 이상, 모델 메모리 1GB 이하, 앱 설치 후 모델 내려받기 1회.

### 6.2 기본 모델 선정 (0단계)

- 후보: 1B~3B급 한국어 가능 오픈 가중치 모델 3~4종.
- 평가 기준: 4비트 양자화 후 한국어 품질, 기준 기기 속도·메모리, **상업적 이용과 미세조정이 허용되는 라이선스**(연구 전용 라이선스 모델은 제외).
- 기기 등급별 운용:
  - A·B등급: 1B급 4비트 모델 기본, A등급에서는 3B급 선택 가능
  - C등급: 언어모델 없이 **규칙 기반 탐침 질문 엔진**으로 대체. 매니페스트의 오개념·변인 정보로 질문 템플릿을 채운다.

규칙 기반 엔진은 1단계 초에 먼저 만든다. 모델이 준비되기 전의 튜터이자, 모델 출력이 가드레일에 걸렸을 때 쓰는 대체 응답이 된다.

### 6.3 학습 데이터

| 출처 | 내용 | 규모 목표 |
|---|---|---|
| 교사 작성 시드 | 실험별 대화 예시: 실험 상태 + 학생 발화 → 좋은 탐침 질문 | 실험당 30~50개 |
| AI 작성 견본(`source: example`) | 형식과 수준을 보여 주는 견본. 이용약관·법무 확인 전까지 학습에서 제외(내보내기 기본값에서 뺀다). 약관이 허용되면 대형 모델 변형 생성 → 교사 검수로 확장 | 실험당 500개 이상(확인 후) |
| 거부 쌍 | 같은 입력에 대한 좋은 응답과 나쁜 응답(정답 누출, 학년 밖 용어, 장황함) 쌍 | 실험당 200쌍 이상 |
| 파일럿 로그 (2단계) | 보호자 동의를 받은 비식별 대화만 학교 서버로 수집 | 파일럿 규모에 따름 |

- 합성 데이터를 만드는 모델은 **출력물로 다른 모델을 학습시켜도 되는 이용약관**인지 먼저 확인한다.
- 아동 대화 데이터는 국내 인프라에서만 저장·학습한다.

### 6.4 학습·배포 파이프라인

1. 지도 미세조정(LoRA)으로 입력 형식, 탐침 질문 문체, 학년별 어휘를 학습시킨다.
2. 선호 최적화(DPO 등)에 거부 쌍을 넣어 정답 누출과 제한 용어를 억제한다.
3. 4비트로 양자화하고 기기 런타임용으로 변환한다. iOS·Android는 llama.cpp 계열 네이티브 플러그인, 크롬북 PWA는 WebGPU 런타임을 쓴다.
4. 평가 게이트를 모두 통과해야 배포한다.
   - 레드팀 정답 노출 0건
   - 제한 용어 0건
   - 교사 품질 평가 기준 이상
   - 기기 속도 기준 충족
5. 모델 레지스트리에 버전을 단원 매니페스트 버전과 묶어 등록하고, 앱이 Wi-Fi에서 내려받는다(MDM 사전 배포도 지원).

### 6.5 실행 시 가드레일 (기기 내)

- **입력 쪽**: 욕설·개인정보 패턴 필터, 범위 밖 질문(숙제 대행, 잡담) 감지 → 정해진 안내 문구로 응답
- **출력 쪽**: 매니페스트의 `forbiddenAnswers`·`limits`와 대조하는 규칙 검사 + 소형 누출 분류기 → 걸리면 1회 재생성, 다시 걸리면 규칙 기반 질문으로 대체
- **로그**: 가드레일에 걸린 건수와 유형만 집계해 서버로 보낸다. 대화 원문은 보내지 않는다.

### 6.6 교사 기능과의 관계

명세서의 "학생-AI 튜터 채팅 요약"은 대화 원문을 서버로 보내지 않는 범위로 바꾼다. 기기 안에서 만든 요약 태그(막힌 오개념 ID, 질문 횟수)만 교사 대시보드로 보낸다. 원문 열람은 2단계에서 보호자 동의 정책과 함께 다시 검토한다.

## 9. 품질·검증 전략

- **시뮬레이션 정확성**: 엔진마다 골든 테스트를 둔다(예: 온도 상승 시 용해량 단조 증가, 보일 법칙 PV≈상수 오차 5% 이내). 과학 교사·교수 자문으로 모델을 검수한다.
- **교육과정 준수**: 매니페스트의 `limits`(다루지 않는 용어·개념)를 튜터 출력과 UI 문구에 자동 검사한다. 예: 5학년 지층 단원에서 "습곡·단층", 3학년 동물 단원에서 "적응".
- **실기기 매트릭스**: 기준 기기 6종 이상에서 Playwright로 E2E를 돌리고, 센서는 하드웨어 인 더 루프 테스트 벤치를 둔다.
- **튜터 평가**: 단원별 평가셋(정답 유도, 탈옥, 부적절 콘텐츠, 학년 수준 어휘)을 모델·프롬프트·가드레일이 바뀔 때마다 회귀 검사한다. 평가 게이트를 통과하지 못한 모델은 배포하지 않는다.
- **접근성**: axe 자동 검사와 스크린리더 수동 점검을 함께 한다.
- **보안·개인정보**: 영상은 기기 밖으로 나가지 않고, xAPI Actor는 가명 ID를 쓰며, 튜터 대화 원문은 기기에 보존 기한을 두고 자동 파기하며 서버로 보내지 않는다.
