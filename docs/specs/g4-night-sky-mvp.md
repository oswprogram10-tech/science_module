# 구현 사양: 4학년 「밤하늘 관찰」 최소 활동 (v0) — 태양계 크기·거리와 북쪽 하늘(관찰 활동 재사용)

> 앞 사양: `phase2-roadmap.md`(순서 16). 관찰 활동 `sky-observation`(6학년 지구의 운동, `g6-earth-motion`)을 재사용한다.
> 새 모듈은 만들지 않는다. **새 보기(view) 두 개**와 **새 정답 규칙 네 개**를 추가한다.

## 0. 결정

- 로드맵 초안의 "달 모양 변화"는 4학년 밤하늘 관찰 성취기준보다 6학년 내용에 가깝다. 그래서 v0에서는 뺀다.
  - 대신 4학년 핵심인 **태양계 행성의 크기·거리 비교**와 **북쪽 하늘에서 북극성 찾기**를 과제로 만든다. 로드맵에 메모한다.
- 관찰 활동의 원칙은 그대로 따른다.
  - 학생이 예측을 고르고, 보기 화면을 조작해 관찰한 뒤, 관찰 기록을 고른다.
  - 기록이 모델 결과와 다르면 정답을 말하지 않고 다시 보게 한다.
- 정답은 모두 **데이터에서 계산**한다.
  - 크기·거리 과제: `@sci/engine-earth`에 행성 표를 두고 계산한다. 표의 수치는 지름(km)과 태양까지 거리(AU)이다.
  - 북극성 과제: 별 목록 좌표(J2000)로 계산한다.
  - 정답 상수를 매니페스트나 코드에 직접 적지 않는다.

## 2. 새 정답 규칙 (`observationAnswerSchema`에 추가, `answerFor`에서 계산)

- `jupiter-earth-size`: `String(Math.round(지름_목성 / 지름_지구))`이다. 결과는 "11"이다.
- `neptune-distance`: `String(Math.round(AU_해왕성 / AU_지구))`이다. 결과는 "30"이다.
- `pointer-star-target`
  1. 메라크(merak)에서 두베(dubhe)로 가는 대원을 따라, 두베에서 두 별 사이 각거리의 5배만큼 더 간 점을 구한다.
  2. 별 목록에서 그 점에 가장 가까운 별의 key를 돌려준다.
  3. 결과는 "polaris"이다(2.6°). 다음으로 가까운 kochab은 14.0°이다. 이 두 각도를 테스트로 고정한다(±0.1°).
- `polaris-motion`
  1. 서울(위도 37.5°) 1월 15일의 오후 9시와 자정에 북극성 위치를 구한다.
  2. 두 위치의 각거리가 1° 미만이면 "nearly-still"이다. 아니면 방위각 증감으로 "east-to-west"나 "west-to-east"이다.
  3. 결과는 "nearly-still"이다.
  - 같은 함수로 북두칠성 dubhe의 각거리를 구하면 20° 이상(약 21.6°)이다. 비교용으로 테스트에 넣는다.
  - 조작 `rotation`(실제/만약에 반대)이 있어도 결과는 "nearly-still"이다.
- `validateSkyObservation`은 그대로 쓴다. 모든 과제의 모델 결과가 선택지 value에 있어야 한다.
- 결과 문자열과 선택지 value는 모두 문자열로 맞춘다.

## 3. 새 보기 (`observationTaskSchema.view`에 추가)

- **`solar-system`: "태양계 모형 보기"**
  - 토글 두 개 "크기 비교"/"거리 비교"를 둔다. 과제의 controls로 정의하고, 정답에는 영향이 없다.
  - **크기 비교**
    - 지구 지름을 10 px로 둔 축척으로 행성 원 8개를 나란히 그린다. 이름과 "지구의 약 n배"는 계산값이다.
    - 단, 과제 기록 전에는 목성의 배수 글자를 숨기고 "?"로 둔다.
    - 태양은 가장자리에 호 일부로 그리고 "태양(지구의 약 109배)"이라고 적는다.
  - **거리 비교**
    - 태양~지구를 1칸으로 하는 거리 막대를 그리고, 행성 점과 이름을 둔다. 0~30칸 눈금이 있다.
    - 해왕성의 칸 수 글자는 기록 전에는 "?"이다. 학생은 눈금을 세어 알아낸다.
    - 좁은 화면에서는 가로로 스크롤되는 띠가 아니라 세로 막대로 바꾼다.
  - 숨김 규칙은 그 과제의 정답이 되는 숫자에만 적용한다. 다른 행성 숫자는 보여 준다.
- **`north-sky`: "북쪽 하늘 보기"**
  - 땅에서 북쪽을 바라본 하늘(지평선, 방위 글자 "북", "북동", "북서")에 위 별 목록을 고도·방위로 그린다.
  - 북두칠성과 카시오페이아는 선으로 잇고 이름을 붙인다. 북극성에는 이름을 붙이지 않는다. 과제 기록 뒤에만 "북극성" 이름이 보인다.
  - 조작
    - 시각 슬라이더: 오후 7시~새벽 3시, 30분 단위. 키보드로 조작할 수 있다.
    - "길잡이 선 보기": 메라크→두베 방향으로 5배 연장한 점선을 그린다.
    - "별 자취 남기기": 시각을 바꿀 때 별의 지난 위치를 흐린 점으로 남긴다.
  - reduced-motion이면 자동 재생하지 않는다.
- 두 보기의 SVG 글자는 13px 이상이다. 다크 모드에서 별(흰색)과 선이 잘 보이게, 밝은 모드에서도 밤하늘 배경은 어둡게 한다(대비 확인).

## 4. 매니페스트 (`content/units/g4-night-sky/manifest.json`)

- 단원 정보
  - id `g4-night-sky`, title "밤하늘 관찰", grade 4, engine "earth"
  - standards `["4과13-01"]`(추정, 고시 대조 필요)
- 실험 정보
  - experiment id `night-sky`, module `sky-observation`, params `{ "latDeg": 37.5 }`
  - title "태양계와 북쪽 하늘 관찰하기", question "태양계 행성의 크기와 거리는 어떻게 다르고, 북쪽 하늘에서 북극성은 어떻게 찾을까?"
- tasks 4개. 각 과제에 기존 5가지 when probe가 모두 있어야 한다.
  1. **planet-size** (view solar-system, answer jupiter-earth-size)
     - 질문: "지구의 지름을 1로 하면 목성의 지름은 약 몇 배일까?"
     - 선택지: "2"(약 2배) / "5"(약 5배) / "11"(약 11배) / "50"(약 50배)
     - controls: compare = size/distance(기본 size)
  2. **planet-distance** (view solar-system, answer neptune-distance)
     - 질문: "태양에서 지구까지를 1칸으로 하면 태양에서 해왕성까지는 약 몇 칸일까?"
     - 선택지: "3" / "10" / "30" / "100"
     - controls: compare(기본 distance)
  3. **find-polaris** (view north-sky, answer pointer-star-target)
     - 질문: "북두칠성 국자 끝의 두 별을 이은 거리의 5배만큼 늘이면 어느 별에 닿을까?"
     - 선택지: polaris "북극성" / kochab "작은곰자리의 밝은 별(코카브)" / capella "카펠라" / vega "직녀성"
  4. **polaris-still** (view north-sky, answer polaris-motion)
     - 질문: "밤 9시부터 자정까지 북극성을 보면 어떻게 움직여 보일까?"
     - 선택지: nearly-still "거의 움직이지 않아요" / east-to-west "동쪽에서 서쪽으로" / west-to-east "서쪽에서 동쪽으로"
     - controls: rotation(기존과 같은 실제/만약에)
- limits: ["천구", "적경", "적위", "광년", "천문단위", "등급", "세차 운동"]
- tutor.forbiddenAnswers
  - "목성은 지구보다 약 11배"
  - "해왕성까지 약 30칸"
  - "북극성은 거의 움직이지 않"
  - "5배만큼 늘이면 북극성"
  - "가장 큰 행성은 목성"
- probes
  - 각 과제의 before-observe, observing, record-mismatch, record-match, prediction-mismatch 문장을 질문형으로 쓴다(예: "눈금을 하나씩 세어 볼까요?", "시각을 바꾸며 북두칠성과 그 별의 움직임을 비교해 볼까요?").
  - record-match는 다음 생각거리(예: "북극성을 찾으면 방향을 알 때 어떻게 도움이 될까요?")로 쓴다.
- 전수 가드에서 probe·피드백이 금지 구절에 걸리지 않아야 한다.

## 5. 검증

- `pnpm typecheck && pnpm test && pnpm build && pnpm e2e`는 모두 종료 코드 0이어야 한다. 기존 기대값은 바꾸지 않는다(단원 수·카드 수 단언만 조정). `g6-earth-motion`의 화면과 테스트는 변하지 않아야 한다.
- 단위 테스트
  - 새 규칙 4개의 결과
  - 각거리 2.6°/14.0° 고정
  - dubhe 20° 이상
  - 행성 표 고정
  - 스키마(view·answer enum)
  - `validateSkyObservation` 통과
  - 튜터 전수 가드
  - 레지스트리
- E2E (`e2e/night-sky.spec.ts`)
  - planet-size: 예측 "2"를 고르고 관찰한다. 크기 비교 화면에서 목성 배수가 "?"인지 확인한 뒤, 기록 "2"를 고르면 다시 보라는 문장이 나온다. "11"을 고르면 맞음 문장과 숫자 11이 보인다.
  - planet-distance: 거리 비교 막대 눈금 30이 보이고, 기록 "30"을 고르면 맞음이다.
  - find-polaris: 길잡이 선을 켜면 점선이 보인다. 기록 전에는 "북극성" 이름이 없고, 기록 뒤에는 있다.
  - polaris-still: 시각을 9시에서 자정으로 옮기면 북두칠성 위치가 바뀐다. 북극성의 화면 위치 변화는 dubhe 위치 변화의 1/20 미만이다.
  - 390px 폭에서 가로 스크롤이 없다. SVG 글자는 13px 이상이다.
  - routing·layout·a11y(밝게·어둡게)에 단원을 추가한다.
- 문서: `docs/testing.md`, README, `phase2-roadmap.md` 16번 행 메모.
