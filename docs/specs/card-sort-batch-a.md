# 확장 사양: 새 카드 분류 활동 4개 (교육과정 원문의 빠진 성취기준, 1차 묶음)

> 근거: 교사 검토 문서 「새 실험 29개 과정 초안」의 ★ 항목 가운데 카드 분류 넷이다. 선생님 확정 전 초안으로 만들고, 카드와 문장은 교사 검수 대상이다.
> 본뜰 것: `docs/specs/g5-weather-dew-fog-cloud-ext.md`(같은 방식의 두 번째 카드 분류 활동), `content/units/g5-weather/manifest.json`의 `dew-fog-cloud`, `WeatherIcons.tsx`, `weather.test.ts`.

## 0. 공통 결정
- 네 활동 모두 기존 단원의 **두 번째 활동**으로 `experiments` 끝에 덧붙인다.
  - module은 card-sort, layout은 groups이다.
  - 첫 활동의 내용과 튜터 시나리오는 바이트 단위로 그대로 둔다.
- 각 단원의 `standards`에 새 성취기준을 더한다. `docs/curriculum-standards.md` 표도 고친다.
- 관찰 근거 원칙과 정답 비공개는 기존 카드 분류와 같다.
  - 관찰 문장에는 보이는 사실만 쓴다. 판정 말이나 정답 무리 이름을 쓰지 않는다.
  - 관찰 기록의 머리말(feature label)은 중립적인 말로 쓴다. 예: "사는 곳", "몸 겉", "잎 모양"
  - 관찰하기 전에는 결과 그림을 보여 주지 않는다.
- 카드 그림은 단순 SVG로 그린다. 단원별 아이콘 파일에 더하고, 그림 안에 글자를 넣지 않는다.
- 튜터
  - probes는 groups 카드 분류의 상황 목록과 같다. 모두 질문형으로 쓰고, finished는 아래에 정한 문장을 쓴다.
  - 전수 가드: probe, 관찰 문장, 화면 문구가 forbiddenAnswers(활용형 포함)와 limits에 걸리지 않아야 한다.
- 튜터 데이터
  - `pnpm tutor:scenarios`로 각 단원 jsonl 뒤에 덧붙인다. 기존 줄은 바이트 단위로 그대로여야 한다.
  - 단원마다 예시를 sft 2, pairs 1, redteam 1개 더한다. 예시는 연결한 시나리오 상태와 맞아야 한다.
- 이 기능이 생긴 뒤의 교사 앱 튜터 질문 편집(`SITUATIONS_BY_KIND`, 교사 카탈로그)에 새 활동이 자동으로 나타나야 한다. 테스트로 확인한다.

## 1. g3-animal 두 번째 활동 `animal-habitat` (4과02-02)
- 제목: "사는 곳과 동물의 생김새"
- 탐구 질문: "사는 곳이 다른 동물들은 생김새가 어떻게 다를까?"
- standards: ["4과02-01", "4과02-02"]

| 카드 | habitat 사는 곳 | fins 몸 옆·등의 얇은 막 | fur 몸 겉 |
|---|---|---|---|
| 붕어 | water | yes | no |
| 상어 | water | yes | no |
| 두더지 | underground | no | yes |
| 지렁이 | underground | no | no |
| 사막여우 | desert | no | yes |
| 낙타 | desert | no | yes |
| 북극곰 | cold | no | yes |
| 북극여우 | cold | no | yes |

- 기준
  - habitat "어디에서 사나요?": 물속 / 땅속 / 사막 / 추운 곳
  - fins "몸에 지느러미가 있나요?": 있다 / 없다
  - fur "몸이 털로 덮여 있나요?": 덮여 있다 / 덮여 있지 않다
  - 주관 기준 "귀여운가요?"
- features action
  - habitat "사는 곳 살펴보기"
  - fins "몸 옆과 등 살펴보기"
  - fur "몸 겉 만져 보기"
- 관찰 문장 예
  - 붕어
    - habitat "민물 속에서 헤엄치며 살아요."
    - fins "몸 옆과 등, 꼬리에 얇은 막이 펼쳐져 있어요."
    - fur "몸 겉이 비늘로 덮여 있어요."
  - 사막여우
    - habitat "모래가 넓게 펼쳐진 뜨겁고 메마른 곳에 살아요."
    - fins "몸 옆과 등에 얇은 막이 없어요."
    - fur "몸 겉이 옅은 갈색 털로 덮여 있고, 귀가 몸에 비해 커요."
  - 나머지 카드도 같은 방식으로 쓴다.
- finished: "사는 곳으로 나눈 무리와 생김새로 나눈 무리를 견주어 볼까요? 같은 곳에 사는 동물끼리 닮은 생김새가 있나요?"
- forbiddenAnswers
  - "지느러미로 헤엄", "지느러미가 있어서 헤엄"
  - "털이 추위를 막", "두꺼운 털로 추위"
  - "큰 귀로 열을", "귀가 커서 열"
  - "환경에 적응", "사는 곳에 적응"
- limits: 진화, 자연 선택, 체온 조절

## 2. g3-plantlife 두 번째 활동 `plant-habitat` (4과03-02)
- 제목: "사는 곳과 식물의 생김새"
- 탐구 질문: "사는 곳이 다른 식물들은 생김새가 어떻게 다를까?"
- standards: ["4과03-01", "4과03-02"]

| 카드 | place 자라는 곳 | float 물 위에 떠 있음 | needle 잎 모양 |
|---|---|---|---|
| 부레옥잠 | water | yes | no |
| 개구리밥 | water | yes | no |
| 검정말 | water | no | no |
| 연꽃 | water | no | no |
| 선인장 | land | no | yes |
| 소나무 | land | no | yes |
| 민들레 | land | no | no |
| 강아지풀 | land | no | no |

- 기준
  - place "어디에서 자라나요?": 물에서 자란다 / 땅에서 자란다
  - float "물 위에 떠 있나요?": 떠 있다 / 떠 있지 않다
  - needle "잎이 가시나 바늘처럼 가늘고 뾰족한가요?": 그렇다 / 그렇지 않다
  - 주관 기준 "예쁜가요?"
- 관찰 문장 예
  - 부레옥잠
    - place "연못 물 위에서 자라요."
    - float "물 위에 떠 있고, 잎자루를 자르면 스펀지처럼 구멍이 많아요."
    - needle "잎이 둥글고 넓적해요."
  - 검정말
    - place "연못 물속에서 자라요."
    - float "줄기와 잎이 모두 물속에 잠겨 있어요."
    - needle "잎이 작고 가늘지만 끝이 뾰족하지 않고 부드러워요."
  - 연꽃
    - place "연못 바닥 흙에 뿌리를 내려요."
    - float "잎이 물 위로 솟아 있고, 뿌리는 바닥에 붙어 있어요."
- finished: "물 위에 떠 사는 식물은 몸의 어느 부분 덕분에 떠 있을 수 있을까요? 관찰 기록에서 찾아볼까요?"
- forbiddenAnswers
  - "공기주머니 덕분에 떠", "공기가 들어 있어서 떠", "공기 때문에 떠"
  - "가시는 물을 아끼", "가시 잎으로 물이 덜"
  - "물에 사는 식물은 떠"
  - "환경에 적응"
- limits: 증산 작용, 기공, 통기 조직

## 3. g4-ecosystem 두 번째 활동 `living-nonliving` (4과14-01)
- 제목: "생태계를 이루는 것 나누기"
- 탐구 질문: "생태계를 이루는 것들을 어떻게 나눌 수 있을까?"
- standards: ["4과14-01", "4과14-02"]

| 카드 | grow 자람 | food 양분 | move 움직임 |
|---|---|---|---|
| 햇빛 | no | no | no |
| 물 | no | no | no |
| 공기 | no | no | no |
| 흙 | no | no | no |
| 돌 | no | no | no |
| 토끼 | yes | yes | yes |
| 참새 | yes | yes | yes |
| 지렁이 | yes | yes | yes |
| 민들레 | yes | yes | no |
| 버섯 | yes | yes | no |

- 기준
  - grow "시간이 지나면 자라거나 수가 늘어나나요?": 그렇다 / 그렇지 않다
  - food "살아가려면 양분이 필요한가요?": 필요하다 / 필요하지 않다
  - move "스스로 자리를 옮겨 다니나요?": 옮겨 다닌다 / 옮겨 다니지 않는다
- 관찰 문장 예
  - 민들레
    - grow "며칠 뒤 다시 보니 잎이 더 커지고 꽃대가 올라왔어요."
    - food "뿌리로 흙 속의 물과 양분을 빨아들여요."
    - move "늘 같은 자리에 뿌리를 내리고 있어요."
  - 돌
    - grow "며칠 뒤 다시 보아도 크기와 모양이 그대로예요."
    - food "먹거나 빨아들이는 것이 없어요."
    - move "누가 옮기지 않으면 그 자리에 그대로 있어요."
  - 물
    - move "낮은 곳으로 흘러가지만, 스스로 갈 곳을 정해 움직이지는 않아요."
  - 공기
    - move "바람이 불면 움직이지만, 스스로 갈 곳을 정하지는 않아요."
- move 기준으로 나누면 살아 있는 것도 두 무리로 갈린다. 의도한 것이다.
  - check-complete와 finished 질문은 "다른 기준으로도 나누어 보자"는 쪽으로 쓴다.
- finished: "햇빛이나 물이 없어지면, 자라고 양분이 필요한 무리에는 어떤 일이 생길까요?"
- forbiddenAnswers
  - "생물 요소", "비생물 요소"(활동 안에서는 이름을 주지 않는다. 마무리 뒤 교사가 도입한다)
  - "움직이지 않아도 생물", "식물도 생물"
  - "버섯은 생물", "버섯도 생물"
- limits: 생산자, 소비자, 분해자, 광합성
  - 생산자·소비자·분해자는 다음 활동(food-web)의 용어일 수 있다. food-web 매니페스트를 확인하고, 그 활동이 쓰는 말이면 limits에서 빼고 forbiddenAnswers로도 넣지 않는다.

## 4. g5-strata 두 번째 활동 `rock-grain` (6과01-02)
- 제목: "퇴적암을 알갱이 크기로 나누기"
- 탐구 질문: "퇴적암을 알갱이의 크기에 따라 어떻게 나눌 수 있을까?"
- standards: 기존 + "6과01-02"
- 카드 이름은 정답이 드러나지 않게 쓴다(예: "회색 암석 가").

| 카드 | grain 알갱이 크기 | smooth 문지른 느낌 | pebble 박힌 조각 | 실제(교사용, 화면에 보이지 않음) |
|---|---|---|---|---|
| 회색 암석 가 | fine | yes | no | 이암 |
| 검은 암석 나 | fine | yes | no | 이암 |
| 붉은 암석 다 | fine | yes | no | 이암 |
| 누런 암석 라 | sand | no | no | 사암 |
| 회색 암석 마 | sand | no | no | 사암 |
| 붉은 암석 바 | sand | no | no | 사암 |
| 얼룩 암석 사 | gravel | no | yes | 역암 |
| 회색 암석 아 | gravel | no | yes | 역암 |

- 기준
  - grain "알갱이는 얼마나 큰가요?": 너무 작아 잘 보이지 않는다 / 모래알만 하다 / 콩알보다 크다
  - smooth "손으로 문지르면 매끄러운가요?": 매끄럽다 / 까끌까끌하다
  - pebble "둥근 돌 조각이 박혀 있나요?": 박혀 있다 / 박혀 있지 않다
  - 주관 기준 "색이 마음에 드나요?"
- 관찰 문장 예
  - 회색 암석 가
    - grain "돋보기로 보아도 알갱이가 잘 보이지 않아요."
    - smooth "문지르면 매끄럽고 손에 고운 가루가 묻어요."
    - pebble "표면이 고르고 박힌 조각이 없어요."
  - 얼룩 암석 사
    - grain "콩알보다 큰 둥근 돌 조각 사이를 모래알이 채우고 있어요."
- 아이콘
  - 알갱이 크기가 보이는 단면 무늬로 그린다.
  - 관찰한 특징에만 돋보기 확대 원을 덧붙인다.
- finished: "알갱이가 아주 작은 암석은 무엇이 쌓여 만들어졌을까요? 모래알만 한 알갱이로 된 암석과 견주어 볼까요?"
- forbiddenAnswers(활용형 포함)
  - "이암", "사암", "역암"(이름은 교사가 마무리에서 도입한다)
  - "진흙이 쌓여", "모래가 쌓여", "자갈이 쌓여"
- limits: 쇄설성, 셰일(이 활동에서), 입도
  - 첫 활동(strata-order)의 카드에 이암·사암·역암·셰일이 이름으로 나오는지 확인한다. 나온다면 이 활동만 금지 구절에 넣는다.
  - 가드는 활동별이므로 첫 활동은 바뀌지 않는다.

## 5. 검증
- `pnpm typecheck && pnpm test && pnpm build && pnpm e2e`가 모두 종료 코드 0이어야 하고, `pnpm tutor:validate`가 통과해야 한다.
- 기존 기대값은 바꾸지 않는다. 단원별 활동 수, 시나리오와 예시 수, 성취기준, "활동 N개" 카드 수만 조정한다.
  - DOM 해시가 바뀌면, 바뀐 부분만 되돌렸을 때 옛 해시가 나오는지 확인한다.
- 단위 테스트(활동마다)
  - 위 표 고정
  - `validateCardSortExperiment`
  - 전수 가드
  - 아이콘 결과와 특징값 일치
  - 관찰 전 결과 그림 없음
- E2E: 단원의 e2e 파일에 더한다(없으면 새로 만든다).
  - 활동 탭으로 이동한다.
  - 관찰 없이 넣으면 미관찰 문장이 나온다.
  - 관찰 뒤 틀리게 넣으면 비교 문장이 나오고, 고치면 맞음 문장이 나온다.
  - 객관 기준을 모두 끝내면 완료 문구가 나온다.
- svg-text·layout·a11y가 새 활동을 검사한다(매니페스트에서 읽는다).
