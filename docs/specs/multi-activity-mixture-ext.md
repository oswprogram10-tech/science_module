# 구현 사양: 한 단원에 여러 활동 지원 + 혼합물의 분리 "분리 방법 고르기" 활동

> 앞 사양: `g5-mixture-mvp.md`(소금과 모래 분리, 변인 실험), `g3-material-mvp.md`(card-sort groups 재사용), 로드맵 14번 메모("체·자석 분리는 확장 과제").
> 지금 앱은 단원마다 `manifest.experiments[0]` 하나만 쓴다. 이 사양은 (가) 여러 활동 구조와 (나) 혼합물의 분리 두 번째 활동으로 나뉜다.

## 가. 한 단원에 여러 활동

### 0. 결정
- 매니페스트는 이미 `experiments` 배열이다. 배열의 모든 항목을 활동으로 쓴다. 순서는 매니페스트 순서이다.
- **주소**
  - `#/unit/{id}`는 지금처럼 **첫 활동**을 연다. 기존 링크와 테스트는 바뀌지 않는다.
  - `#/unit/{id}/{experimentId}`는 해당 활동을 연다.
  - 모르는 experimentId는 첫 활동으로 돌린다.
- **레지스트리** (`apps/student/src/units.ts`)
  - `UnitEntry`(ok)에 `activities: ActivityEntry[]`를 더한다. ActivityEntry는 `{ activity, experiment, module }`이다.
  - 기존 최상위 `activity/experiment/module` 필드는 첫 활동 값으로 그대로 둔다(기존 코드·테스트 호환).
  - 검증은 지금처럼 모든 experiment를 검사한다.
- **화면**
  - 활동이 2개 이상인 단원은 단원 머리 아래에 활동 탭을 둔다. 탭은 `role="tablist"`이고 탭마다 `aria-selected`를 둔다. 탭 이름은 experiment.title이며, 앞에 "활동 1", "활동 2"를 붙인다.
  - 탭을 바꾸면 주소가 바뀌고, 그 활동의 상태는 새로 시작한다(지금 단원 이동과 같은 방식).
  - 활동이 1개인 단원은 탭을 그리지 않는다. 화면과 DOM은 지금과 같아야 한다(무변화 테스트).
  - 단원 목록 카드는 단원당 하나 그대로이다. 활동이 여럿이면 카드에 "활동 2개"를 표시한다.
- **교실**
  - 상태 메시지에 선택 필드 `experimentId`(shortText)를 더한다. 오래된 클라이언트는 이 필드를 보내지 않아도 된다(하위 호환).
  - 교사 대시보드는 단원에 활동이 여럿일 때 단원 이름 옆에 활동 이름을 보인다. 교사 앱의 단원 목록(`apps/teacher/src/units.ts`)도 활동 이름을 알아야 한다.
- **xAPI**: activityId는 이미 `{unitId}/{experimentId}`이다. 그대로 둔다.
- **탐구 기록장**: 항목이 unitId와 kind 단위라 그대로 둔다. 진로 단원의 영역·기록 집계도 바뀌지 않는다.
- **튜터 데이터**
  - 시나리오 생성기는 단원의 모든 experiment를 순서대로 돈다. 첫 experiment의 시나리오 id는 **바이트 단위로 그대로**이고, 새 활동의 시나리오는 뒤에 덧붙인다.
  - 시나리오에 `experimentId`를 둔다(없으면 첫 활동).
  - 작성실 데이터의 단원 금지 구절과 학년 밖 용어는 단원 안 모든 활동의 합집합으로 한다(더 엄격한 쪽).
  - 가져오기(import) 검증은 시나리오의 활동 기준으로 한다.

### 1. 테스트
- 단위: parseRoute(두 형식, 모르는 활동), 레지스트리 activities, 활동 1개 단원의 화면 무변화(대표 단원 몇 개의 렌더 결과 동일), 교실 프로토콜 하위 호환, 시나리오 id 안정성.
- E2E: 탭 전환과 주소, 새로 고침 뒤 같은 활동, 키보드로 탭 이동, 교실 연결 시 교사 화면의 활동 이름, routing·layout·a11y·svg-text가 두 번째 활동도 지남.

## 나. 혼합물의 분리 두 번째 활동: "분리 방법 고르기" (card-sort groups)

### 0. 결정
- 기존 소금과 모래 실험은 첫 활동으로 그대로 둔다.
- 두 번째 활동은 혼합물 카드 6장을 성질에 따라 나누는 카드 분류이다. 학생은 각 혼합물을 관찰해(돋보기: 크기 비교·자석 대 보기·물에 넣어 보기) "어떤 성질이 다른가"로 나눈다. 다 나눈 뒤 끝 질문으로 "그러면 어떤 방법으로 분리할 수 있을까?"를 생각하게 한다.
- 관찰 근거 원칙과 정답 비공개는 g3-animal·g3-material과 같다.
- 로드맵 초안의 "거름" 단계는 첫 활동(소금과 모래)이 다룬다.

### 1. 카드와 특징 (교사 검수 대상)

| 카드 | size 알갱이 크기가 다름 | magnet 한 가지가 자석에 붙음 | dissolve 한 가지만 물에 녹음 |
|---|---|---|---|
| 콩과 좁쌀 | yes | no | no |
| 쌀과 모래 | yes | no | no |
| 철 가루와 모래 | no | yes | no |
| 철 구슬과 유리 구슬(크기 같음) | no | yes | no |
| 소금과 모래 | no | no | yes |
| 설탕과 콩 | yes | no | yes |

- 설탕과 콩은 체와 물 두 방법이 모두 가능하다. 끝 질문에서 "두 가지 방법이 다 될 것 같은 혼합물이 있나요?"로 다룬다.
- **기준**(groups)
  - size "두 가지의 알갱이 크기가 다른가요?": 다르다 / 비슷하다
  - magnet "한 가지가 자석에 붙나요?": 붙는다 / 붙지 않는다
  - dissolve "한 가지만 물에 녹나요?": 녹는다 / 녹지 않는다
  - 주관 기준 "보기에 깨끗한가요?": 깨끗해 보인다 / 지저분해 보인다 (`objective: false`)
- **features action**: "크기 비교하기", "자석 대 보기", "물에 넣어 보기"
- **관찰 문장**(카드 × 특징, 판정 단어 없이 보이는 사실만). 예: 철 가루와 모래 / magnet: "자석을 가까이 대면 검은 가루만 자석에 달라붙어요."
  - 콩과 좁쌀
    - size: "콩은 크고 좁쌀은 아주 작아요."
    - magnet: "자석을 대도 아무것도 붙지 않아요."
    - dissolve: "물에 넣어도 콩과 좁쌀 모두 그대로 남아 있어요."
  - 쌀과 모래
    - size: "쌀알은 모래알보다 훨씬 커요."
    - magnet: "자석을 대도 아무것도 붙지 않아요."
    - dissolve: "물에 넣어도 쌀과 모래 모두 그대로 남아 있어요."
  - 철 가루와 모래
    - size: "두 가루의 알갱이 크기가 비슷해요."
    - magnet: "자석을 가까이 대면 검은 가루만 자석에 달라붙어요."
    - dissolve: "물에 넣어도 두 가루 모두 바닥에 가라앉아요."
  - 철 구슬과 유리 구슬
    - size: "두 구슬의 크기가 같아요."
    - magnet: "자석을 대면 철 구슬만 끌려와요."
    - dissolve: "물에 넣어도 두 구슬 모두 그대로예요."
  - 소금과 모래
    - size: "소금 알갱이와 모래알의 크기가 비슷해요."
    - magnet: "자석을 대도 아무것도 붙지 않아요."
    - dissolve: "물에 넣고 저으면 소금은 보이지 않게 되고 모래는 바닥에 남아요."
  - 설탕과 콩
    - size: "콩은 크고 설탕 알갱이는 작아요."
    - magnet: "자석을 대도 아무것도 붙지 않아요."
    - dissolve: "물에 넣고 저으면 설탕은 보이지 않게 되고 콩은 그대로 남아요."
- **카드 그림**: 두 재료를 섞어 놓은 단순 SVG 6종(`MixtureIcons.tsx`)이다.
  - 시험한 특징에만 결과 그림을 덧붙인다(자석에 달라붙음, 녹아 사라짐, 크기 비교선). 관찰 전에는 결과를 드러내지 않는다(g3-material 방식).
  - 그림 안에는 글자를 넣지 않는다.
- **튜터**
  - forbiddenAnswers(활용형 포함)
    - "철 가루는 자석에 붙"
    - "자석으로 철 가루를 분리"
    - "체로 콩과 좁쌀을"
    - "소금은 물에 녹"
    - "크기가 다르면 체"
    - "녹으면 물에 녹여 거르"
    - "설탕과 콩은 두 가지 방법"
    - "깨끗해 보이는가는 분류 기준이 될 수 없"
  - limits: ["밀도", "자성", "용해도", "여과", "증류", "크로마토그래피"]
  - probes: g3-material과 같은 상황 목록이다. finished 질문은 "성질에 따라 나누어 보았어요. 그러면 각 무리의 혼합물은 어떤 도구로 분리할 수 있을까요? 두 가지 방법이 다 될 것 같은 혼합물도 있나요?"이다.
- **experiment id** `separation-methods`, title "혼합물의 성질에 따라 분리 방법 고르기", question "혼합물을 이루는 물질의 성질이 다르면 어떻게 분리할 수 있을까?"

### 2. 검증
- `pnpm typecheck && pnpm test && pnpm build && pnpm e2e` 모두 종료 코드 0, `pnpm tutor:validate` 통과. 기존 기대값은 바꾸지 않는다(단원 수·카드 수·가드 목록만 조정).
- 단위
  - §1 표 고정
  - `validateCardSortExperiment`
  - 전수 가드
  - 아이콘 결과와 특징값 일치
  - 관찰 전 결과 그림 없음
- E2E (`e2e/mixture.spec.ts`에 추가)
  - 활동 탭으로 이동한다.
  - "한 가지가 자석에 붙나요?"로 관찰 없이 넣으면 미관찰 문장이 보인다.
  - 관찰 뒤 철 구슬과 유리 구슬을 "붙지 않는다"에 넣으면 다시 비교 문장이 보이고, 고치면 맞음 문장이 보인다.
  - 두 기준을 끝내면 완료 문구가 보인다.
  - 첫 활동(소금과 모래)의 기존 E2E는 그대로 통과한다.
