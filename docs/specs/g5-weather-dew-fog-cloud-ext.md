## 1. 카드와 특징 (교사 검수 대상)

| 카드(label) | surface 물체 겉에 붙어 있음 | air 공기 중에 떠 있음 | high 높은 하늘에 있음 |
|---|---|---|---|
| 아침 풀잎에 맺힌 물방울 | yes | no | no |
| 차가운 컵 겉에 맺힌 물방울 | yes | no | no |
| 겨울 아침 창문 안쪽에 맺힌 물방울 | yes | no | no |
| 새벽 강가를 덮은 뿌연 공기 | no | yes | no |
| 산골짜기에 낮게 깔린 뿌연 공기 | no | yes | no |
| 하늘 높이 떠 있는 하얀 구름 | no | yes | yes |
| 비행기 창밖으로 보이는 구름 | no | yes | yes |
| 비가 오기 전 하늘을 덮은 먹구름 | no | yes | yes |

- **기준**(groups)
  - surface "물체의 겉에 붙어 있나요?": 붙어 있다 / 붙어 있지 않다
  - air "공기 중에 떠 있나요?": 떠 있다 / 떠 있지 않다
  - high "땅에서 먼 높은 하늘에 있나요?": 높은 하늘에 있다 / 땅 가까이에 있다
  - 주관 기준 "보기에 아름다운가요?": 아름답다 / 아름답지 않다 (`objective: false`)
- **features action**
  - surface "가까이에서 만져 보기"
  - air "주변 공기 살펴보기"
  - high "어디쯤 있는지 올려다보기"
- **관찰 문장**: 카드마다 특징 셋을 쓴다. 판정 단어 없이 보이는 사실만 쓴다. 예를 들면 다음과 같다.
  - 아침 풀잎
    - surface: "풀잎 겉에 작은 물방울이 동그랗게 붙어 있어요."
    - air: "물방울은 풀잎에 붙어 있고, 둘레 공기는 맑아요."
    - high: "땅 가까이 풀잎 위에 있어요."
  - 새벽 강가
    - surface: "손을 대도 무엇이 붙어 있지는 않아요."
    - air: "강 위 공기가 뿌옇게 흐려 멀리가 잘 보이지 않아요."
    - high: "강물 바로 위, 땅 가까이에 깔려 있어요."
  - 하얀 구름
    - surface: "어디에 붙어 있지 않아요."
    - air: "하늘에 하얗게 떠 있어요."
    - high: "고개를 들어야 보일 만큼 높은 하늘에 있어요."
  - 나머지 카드도 같은 방식으로 쓴다. 판정 단어("이슬", "안개", "구름"이라는 정답 이름을 무리 이름처럼 쓰는 것)는 관찰 문장에 넣지 않는다. 카드 이름의 "구름"은 그대로 둔다.
- **카드 그림**: 단순 SVG 8종(`WeatherIcons.tsx`)으로 그린다. 그림 안에 글자를 넣지 않는다. 관찰한 특징에만 결과 표시를 덧붙인다(예: 물방울 강조, 높이 눈금). 관찰 전에는 결과를 드러내지 않는다(기존 카드 분류 방식).
- **튜터**
  - probes: 기존 카드 분류(groups)와 같은 상황 목록이다. 모두 질문형으로 쓴다.
    - finished: "어디에 생기는지에 따라 나누어 보았어요. 그러면 이슬, 안개, 구름은 어떤 점이 같을까요? 셋 다 무엇으로 이루어져 있을지 생각해 볼까요?"
  - forbiddenAnswers(활용형 포함)
    - "모두 물방울" / "셋 다 물방울" / "모두 작은 물방울"
    - "수증기가 응결" / "수증기가 엉겨" / "수증기가 물방울로 변"
    - "이슬은 물체 표면" / "이슬은 물체에 맺히" / "이슬은 물체 겉에"
    - "안개는 땅 가까이" / "안개는 지표 가까이" / "안개는 지면 가까이"
    - "구름은 높은 하늘" / "구름은 하늘 높이"
    - "아름다운가는 분류 기준이 될 수 없"
  - limits: 응결핵, 포화, 이슬점, 상대 습도, 단열 팽창
  - 전수 가드에서 probe·관찰 문장·화면 문구가 금지 구절과 limits에 걸리지 않아야 한다.

## 2. 검증
- `pnpm typecheck && pnpm test && pnpm build && pnpm e2e`가 모두 종료 코드 0이어야 하고, `pnpm tutor:validate`가 통과해야 한다.
- 기존 기대값은 바꾸지 않는다. 단원별 활동 수, 시나리오와 예시 수, 성취기준, "활동 N개" 카드 수만 조정한다.
- 단위 테스트
  - §1 표 고정
  - `validateCardSortExperiment`
  - 전수 가드
  - 아이콘 결과와 특징값 일치
  - 관찰 전 결과 그림 없음
- E2E (`e2e/weather.spec.ts`에 추가)
  - 활동 탭으로 이동한다.
  - "물체의 겉에 붙어 있나요?"로 관찰 없이 넣으면 미관찰 문장이 나온다.
  - 관찰 뒤 "새벽 강가"를 "붙어 있다"에 넣으면 비교 문장이 나오고, 고치면 맞음 문장이 나온다.
  - 객관 기준 두 개를 끝내면 완료 문구가 나온다.
  - 첫 활동(해륙풍)의 기존 E2E는 그대로 통과한다.
