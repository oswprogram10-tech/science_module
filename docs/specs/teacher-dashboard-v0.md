# 구현 사양: 교사 대시보드 v0 — 수업 연결, 모둠 실시간 현황, 안전 알림, 모두 멈춤

> 근거: `docs/DEVELOPMENT_PLAN.md` §3.1(MVP: 교사 대시보드 최소 기능: 모둠 실시간 그리드, 안전 알림, 일시정지), §4(아키텍처의 Realtime Hub), §6.6(튜터 원문은 서버로 보내지 않음), §7.1 S5, §11(학교 무선망 불안정).
> 범위: **수업 중계 서버(메모리 상태), 공용 메시지 규격, 교사 대시보드 앱, 학생 앱의 수업 참여·상태 보내기·멈춤 화면, 테스트, 실행 안내.** 로그인·학급 명부·기록 저장(DB)·배포는 범위 밖이다.

## 0. 결정

| # | 결정 | 이유 |
|---|---|---|
| R1 | v0 서버는 **Fastify + `@fastify/websocket`**, 상태는 메모리에만 둔다. 계획서의 NestJS·PostgreSQL은 로그인·기록 저장이 필요한 2단계에서 도입한다. 계획서 결정 기록 D9에 남긴다. | v0는 중계와 수업 동안의 상태만 필요하다. 무거운 프레임워크는 학습·운영 비용만 늘린다. |
| R2 | 학생은 **수업 코드 + 모둠 번호(1~12)**로만 참여한다. 이름·학번은 받지 않는다. | 아동 개인정보 최소화 |
| R3 | 학생 기기는 **진행 요약만** 보낸다. 단원, 단계, 시행 수, 마지막 상황 종류, 예측과 결과가 달랐는지, 안전 경고 종류와 시각이다. 튜터 대화·카메라 영상·센서 원자료는 보내지 않는다. | 계획서 §6.6, 비전은 기기 내 처리 원칙 |
| R4 | 수업 연결은 **선택 기능**이다. 서버 주소가 없거나 연결이 끊겨도 학생 앱의 모든 실험은 그대로 동작한다. 끊기면 자동 재연결하고, 재연결되면 최신 상태를 한 번 다시 보낸다. | 학교 무선망 불안정(계획서 §11) |
| R5 | 교사 권한은 **수업을 만들 때 받는 비밀 토큰**(128비트 무작위)으로 확인한다. 토큰은 교사 화면의 메모리와 URL 해시에만 둔다. 학생 코드는 6자다. 헷갈리는 0·O·1·I·L은 쓰지 않는다. | 로그인 없이도 학생이 교사 기능을 쓰지 못하게 |
| R6 | 서버 주소는 빌드 변수 `VITE_CLASSROOM_URL` 또는 주소 `?classroom=` 값으로 정한다. 둘 다 없으면 학생 앱의 수업 참여 기능을 숨긴다. | 서버를 어디서 돌릴지(교실 노트북, 공공 클라우드)는 운영 결정이므로 코드에 박지 않는다. |

## 1. 공용 규격 (`packages/classroom`, `@sci/classroom`)

zod 스키마와 타입을 둔다. 서버, 교사 앱, 학생 앱이 같은 것을 쓴다. 모든 메시지는 JSON이고 `{ t: "<종류>", ... }` 형태이며, 한 메시지는 8 KB 이하다.

- **학생 → 서버**
  - `join { code, group: 1..12, deviceTier?: 'A'|'B'|'C', appVersion }`
  - `status { unitId, activity: 'variable'|'classify'|'observe', phase, trials, lastKind?, mismatch?, safetyLocked }`
    - phase: `'designing'|'running'|'reviewing'|'idle'`
    - lastKind: 변인 실험은 analysis.kind, 분류·관찰은 상황 키
    - safetyLocked: 경고 배너 때문에 실험이 잠겨 있는지
  - `safety { type: 'NO_GOGGLES'|'NO_GLOVES'|'SPILL'|'FOOD', at }`
  - `safetyClear { type }`: 학생이 "착용했어요" 등을 눌러 배너를 닫음
- **교사 → 서버**: `create {}`, `watch { code, token }`, `pause { on }`, `ack { group, type }`(교사가 경고를 확인함), `end {}`
- **서버 → 학생**: `joined { code, group }`, `pause { on }`, `ended {}`, `error { code }`
- **서버 → 교사**: `created { code, token }`, `snapshot { code, paused, groups: GroupView[] }`(변경이 있을 때마다, 초당 최대 4회로 묶어서), `error { code }`
- **`GroupView`**: `{ group, online, lastSeen, deviceTier?, unitId?, activity?, phase?, trials, lastKind?, mismatch, safety: { type, at, acked }[], safetyLocked }`
- **오류 코드**: `bad_message`, `no_class`, `bad_token`, `group_taken`(같은 모둠 번호가 이미 연결 중), `class_full`, `rate_limited`
- **순수 함수 `reduce(state, event) → state`**: 서버 상태 변화를 담는다. 테스트 대상이다.

## 2. 수업 중계 서버 (`apps/server`, `@sci/server`)

- Fastify + `@fastify/websocket`. 포트는 `PORT`(기본 8787)이고 경로는 `/ws`. `GET /health`가 `{ ok: true, classes }`를 돌려준다.
- **수업**
  - `create`하면 코드와 토큰을 만든다.
  - 수업당 모둠은 최대 12개다.
  - 연결이 하나도 없이 6시간이 지나거나 `end`가 오면 지운다.
  - 서버 하나에 수업은 최대 50개다.
- **제한**
  - 연결당 초당 메시지 10개
  - 메시지 8 KB
  - zod 검증에 실패하면 `error bad_message`로 응답하고, 3번 실패하면 연결을 끊는다.
- **Origin 허용 목록**: `ALLOWED_ORIGINS`(쉼표 구분). 비어 있으면 개발용으로 모두 허용하고 시작 로그에 경고를 남긴다.
- **모둠 연결**
  - 같은 모둠 번호로 새 연결이 오면 `group_taken`으로 거절한다.
  - 기존 연결이 75초 이상 응답이 없으면 새 연결로 바꾼다(학생 기기 재접속 대비). ping 간격(30초)의 2.5배다(v0.1).
  - 30초마다 ping을 보낸다.
- **로그**: 수업 코드와 모둠 번호, 이벤트 종류만 남긴다. 메시지 본문은 남기지 않는다.
- 저장소에 DB나 파일을 쓰지 않는다.

## 3. 교사 대시보드 앱 (`apps/teacher`, Vite + React 19)

학생 앱과 같은 디자인 토큰(색·글꼴·다크 모드)과 접근성 규칙을 따른다.

- **시작 화면**: "수업 만들기" 버튼을 누르면 서버에 `create`를 보내고, 받은 토큰을 URL 해시에 넣는다(`#class=<code>&token=<token>`). 새로고침해도 같은 수업을 다시 본다.
- **수업 화면**
  - **머리글**
    - 큰 글씨의 수업 코드(학생에게 보여 주는 용도)와 연결 상태
    - "모두 멈춤" / "다시 시작" 토글: 누르면 학생 화면이 잠긴다.
    - "수업 끝내기"(확인 단계 포함)
  - **모둠 카드 격자**(모둠 번호 순, 1~12)
    - 모둠 번호, 연결 상태(초록 "연결됨" / 회색 "끊김 · n분 전"), 단원 이름, 단계("실험 설계 중", "실험 중", "결과 보는 중"), 시행 수
    - 최근 상황 한 줄(예: "두 조건을 함께 바꿈", "예측과 다른 결과"). 사람이 읽는 문장으로 바꿔 보여 준다.
    - 기기 등급은 작게 표시한다.
  - **안전 경고**
    - 확인하지 않은 경고가 있는 카드는 붉은 테두리와 "⚠ 보안경 안 씀 · 10:42" 같은 표시, "확인" 버튼을 가진다.
    - 화면 위 알림 띠(`role="alert"`)에 미확인 경고 개수를 보여 준다.
    - 경고가 생기면 경고음을 한 번 낸다. 첫 클릭 뒤에만 재생되므로, 시작 화면에 "알림 소리 켜기" 버튼을 둔다.
  - **정렬**: 미확인 경고가 있는 모둠, 잠긴 모둠, 나머지 순서로 위에 둔다. "모둠 번호 순" 토글도 둔다.
- **단원 이름**: 학생 앱의 단원 목록(매니페스트)에서 가져와 보여 준다. 공용 import는 `content/units`를 읽는 작은 모듈로 한다.
- 서버 주소는 `VITE_CLASSROOM_URL` 또는 `?classroom=`로 정한다. 없으면 `ws://localhost:8787/ws`(개발용).

## 4. 학생 앱 변경 (`apps/student`)

- **수업 참여**
  - 단원 목록 머리글에 "수업 참여" 버튼을 둔다(R6: 서버 주소가 있을 때만).
  - 누르면 대화상자가 열린다. 수업 코드 6자와 모둠 번호(1~12 버튼)를 받는다.
  - 참여하면 머리글에 "수업 ABC123 · 3모둠 · 연결됨"이 보인다. 끊기면 "다시 연결 중"이 보인다.
  - "수업 나가기"를 둔다.
  - 참여 정보는 sessionStorage에 두어 새로고침해도 다시 참여한다(try/catch).
- **상태 보내기**
  - 실험 화면의 상태가 바뀔 때 `status`를 보낸다. 묶어서 초당 1회 이하로 보낸다.
  - 기존 xAPI emit 지점과 런타임 상태에서 만든다. 활동 유형 세 가지(변인·분류·관찰) 모두 보낸다.
  - 단원 목록에 있으면 `phase: 'idle'`이다.
  - 안전 경고가 뜨면 `safety`를, 학생이 닫으면 `safetyClear`를 보낸다. 모의 감지기(`?dev=1`) 경고도 같은 경로로 보낸다. 실제 감지 모델이 생기면 그대로 이어진다.
- **멈춤 화면**
  - `pause on`을 받으면 화면 전체를 덮는 막을 띄운다. 문구는 "선생님 말씀을 들어요 ✋"이고, 입력을 막으며 `aria-live="assertive"`로 알린다.
  - 재생 중인 시뮬레이션은 멈춘다(플레이헤드 고정).
  - `pause off`면 막을 걷고 이어서 한다.
  - 연결이 끊긴 상태에서는 멈춤을 걸지 않는다(교사가 확인할 수 없으므로).
- 연결 코드는 `apps/student/src/classroom/`에 둔다. 서버 주소가 없으면 번들에서 큰 부분이 빠지게 한다(동적 import 권장).

## 5. 테스트

- **단위**
  - `@sci/classroom` 스키마(정상·잘못된 메시지)
  - `reduce`의 시나리오: 참여, 중복 모둠, 재접속 교체, 경고·확인·해제, 멈춤, 만료
  - 문장 변환(lastKind → 한국어)
- **통합**(vitest): 서버를 임의 포트로 띄우고 ws 클라이언트로 확인한다.
  - 교사 create/watch, 학생 join/status/safety → 교사 snapshot
  - pause가 학생에게 전달됨
  - 잘못된 토큰 거절, rate limit
- **E2E**(Playwright)
  - `webServer`를 배열로 바꿔 학생 앱, 교사 앱, 서버를 함께 띄운다. 기존 E2E는 서버 없이도 그대로 통과해야 한다. 학생 앱 기본 설정에 서버 주소가 없으므로, 수업 테스트만 `?classroom=`을 붙인다.
  - 새 테스트:
    1. 교사가 수업을 만들고, 학생 두 명(2모둠, 5모둠)이 참여하면 카드에 "연결됨"이 보인다.
    2. 2모둠 학생이 용해와 용액에서 한 번 실행하면 교사 카드의 시행 수가 1이 된다.
    3. 5모둠이 `?dev=1` 모의 경고를 일으키면 교사 화면에 경고 띠와 카드가 붉게 표시된다. 교사가 "확인"을 누르면 사라진다.
    4. 교사가 "모두 멈춤"을 누르면 두 학생 화면에 막이 뜨고, "다시 시작"을 누르면 사라진다.
    5. 서버를 내린 상태에서도 학생 앱 실험이 동작하고 "다시 연결 중"이 보인다.
  - axe 검사에 교사 화면(밝게·어둡게)을 추가한다.
- CI: E2E 작업이 서버도 띄우도록 설정한다.

## 7. 검증

- `pnpm typecheck && pnpm test && pnpm build && pnpm e2e` 모두 종료 코드 0.
- 기존 기대값은 바꾸지 않는다(단위 521, E2E 174).
- 수업 기능을 쓰지 않는 학생 앱의 번들 크기 증가는 10 kB(gzip) 이하로 유지하고 보고한다.

## 8. 리뷰 반영(v0.1)

독립 리뷰에서 나온 보완 사항이다. 위 규칙 중 충돌하는 것(모둠 교체 시간 30초 → 75초)은 이 절이 우선한다.

**서버**
1. **교사 부재 중 멈춤 해제**: 멈춤 상태에서 교사 연결이 하나도 없이 30초가 지나면 서버가 `paused=false`로 돌리고 학생에게 `pause { on:false }`를 보낸다.
2. **반쯤 끊긴 소켓**: 30초 ping마다 직전 ping 이후 pong이 없던 소켓은 `terminate()`한다. 10초 안에 create/watch/join에 성공하지 못한 연결은 닫는다(1008). 열려 있는 소켓은 서버 전체 600개, IP당 80개까지다(학교는 공용 IP 하나를 쓰므로 80보다 낮추지 않는다). 초과는 close code 1013으로 거절한다.
3. **수업 만들기 남용 방지**: 교사 연결이 30분 동안 하나도 없던 수업은(학생이 남아 있어도) 지운다(기존 6시간 유휴 규칙은 그대로). IP당 `create`는 시간당 10번이며 넘으면 `error rate_limited`. 환경 변수 `CREATE_SECRET`이 있으면 `create`에 `secret`(문자열, 64자 이하, 선택 필드)이 같아야 하고, 틀리거나 없으면 `error bad_secret`(오류 코드 추가).
4. **중복 create/watch는 멱등**: 이미 교사인 연결이 `create`/`watch`를 다시 보내면 `bad_message` 대신 현재 `created`·`snapshot`을 다시 보낸다.
5. **STALE_MS = 75초**(ping은 30초 그대로).
6. 기타: 속도 제한을 5초 동안 계속 넘기면 연결을 닫는다(1008). Origin 비교는 소문자로 바꾸고 끝의 `/`를 뗀 값으로 한다. 쓰기 대기량(`bufferedAmount`)이 1 MB를 넘는 교사 소켓에는 snapshot을 보내지 않고 다음 기회로 미룬다. 규격 위반 누적 횟수(`bad`)는 일부러 줄지 않는다.
7. **오래된 안전 경고**: 학생의 `status`가 `safetyLocked=false`로 오거나, 잠금 없음으로 끝난 모둠이 다시 `join`하면, 교사가 이미 확인한(acked) 그 모둠의 경고를 지운다.

**교사 앱**
- 「수업 만들기」는 답이 올 때까지 잠근다. `created` 뒤에 온 `bad_message`는 치명적으로 다루지 않는다.
- `bad_secret`을 받으면 「수업 만들기 비밀번호」 입력칸을 보여 주고 다시 시도한다. 주소의 `?key=`로 미리 채울 수 있다.

**학생 앱**
- 멈춤 막 안에 「수업 나가기」 버튼을 둔다(아래 화면이 inert여도 키보드로 닿는다).
- 재연결 뒤 보내기: 끊긴 동안 쌓인 이벤트를 줄이고(status는 마지막 하나, safety/safetyClear는 종류마다 마지막 하나), 8개까지만 두며, `joined` 뒤 150ms 이상 간격으로 보낸다.
- 참여한 뒤 서버의 `bad_message`는 수업에서 내보내지 않고 `console.warn`만 남긴다. 보내는 글자 필드는 규격의 최대 길이에 맞춰 자른다.
- 수업 화면 조각(Host, Control)은 `ErrorBoundary`로 감싸 불러오기에 실패하면 아무것도 그리지 않는다(R4).
- `?classroom=`는 개발 서버(`import.meta.env.DEV`)이거나 그 서버 주소의 호스트가 빌드 변수 `VITE_CLASSROOM_ALLOWED_HOSTS`(쉼표 구분)에 있을 때만 받는다(R6 보완). 수업 E2E는 `VITE_CLASSROOM_ALLOWED_HOSTS=localhost`로 빌드한다.
