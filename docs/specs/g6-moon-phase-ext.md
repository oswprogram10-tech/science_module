# 확장 사양: 6학년 「지구의 운동」에 달 모양 변화 과제 추가 (관찰 활동)

> 앞 사양: `g4-night-sky-mvp.md`(관찰 활동에 보기·정답 규칙 추가), 6학년 지구의 운동 관찰 활동(`content/units/g6-earth-motion/manifest.json`).
> 로드맵 16번(밤하늘 관찰)에서 4학년에 맞지 않아 뺀 "달 모양 변화"를 6학년 단원의 관찰 과제로 넣는다. 새 모듈은 만들지 않는다.

## 0. 결정

- 새 보기 `moon` 하나와 새 정답 규칙 두 개를 더한다. 과제는 **기존 과제 뒤에 덧붙인다**.
  - 튜터 시나리오 id(`g6-earth-motion-sNNN`)와 예시 기록이 기존 과제의 번호를 그대로 쓰므로, 기존 과제 순서·내용을 바꾸지 않는다.
  - 기존 g6-earth-motion 시나리오와 예시 기록은 바이트 단위로 그대로여야 한다.
- 모델은 **교사 검수 대상**인 단순화이다.
  - 달은 천구 적도 위를 돈다(적위 0°).
  - 삭망 주기는 29.53일, 관측은 서울(북위 37.5°) 저녁 7시이다.
  - 달 궤도 기울기, 이심률, 대기 굴절은 무시한다.
- 용어: "달", "초승달", "상현달", "보름달", "하현달", "그믐달", "음력"을 쓴다. 위상·이각·삭망월·황도는 `limits`에 넣는다.

## 1. 모델 (`@sci/engine-earth`, `moon.ts`)

- 음력 날짜 d(정수 1~29)에서 아래 값을 구한다.
  - 달이 태양에서 떨어진 각 `φ = 360·d/29.53`(°)
  - 밝은 부분의 비율 `frac = (1 − cos φ)/2`
  - 차오르는 중인가 `waxing = φ < 180`. 북반구에서 남쪽을 보면 차오를 때는 오른쪽(서쪽)이 밝다.
  - 남중 시각 `transit = 12 + 24·d/29.53`(시)
- **저녁 7시 위치**: 기존 `sunPositionAtDeclination({ hour: 12 + (19 − transit), decDeg: 0, latDeg: 37.5 })`로 고도·방위를 구한다. 고도 ≤ 0이면 "이 시각에는 달이 보이지 않아요"이다.
- **모양 이름**(φ 기준)

  | φ | 이름 |
  |---|---|
  | < 22.5 또는 ≥ 337.5 | 보이지 않음(삭 무렵) |
  | < 67.5 | 초승달 |
  | < 112.5 | 상현달 |
  | < 157.5 | 상현과 보름 사이 |
  | < 202.5 | 보름달 |
  | < 247.5 | 보름과 하현 사이 |
  | < 292.5 | 하현달 |
  | 그 밖 | 그믐달 |

- **새 정답 규칙**(`observationAnswerSchema`에 추가, `answerFor`에서 계산)
  - `moon-evening-change`: d=3과 d=10의 저녁 7시 값을 비교한다. frac이 늘고 방위가 남쪽·동쪽으로 옮겨 가면(방위각 감소) "waxes-east"이다. frac이 줄고 서쪽으로 옮겨 가면 "wanes-west"이다. 둘 다 같으면 "same"이다. 결과는 "waxes-east"이다.
  - `full-moon-day`: d=1~29 중 frac이 가장 큰 날을 문자열로 돌려준다. 결과는 "15"이다.
- **기준값**(테스트로 고정, 소수 첫째 자리)

  | d | φ | frac | 저녁 7시 고도 | 방위각 |
  |---|---|---|---|---|
  | 1 | 12.2 | 0.011 | −2.2 | 271.7 |
  | 3 | 36.6 | 0.098 | 17.0 | 256.5 |
  | 8 | 97.5 | 0.566 | 51.9 | 192.2 |
  | 10 | 121.9 | 0.764 | 49.4 | 153.5 |
  | 15 | 182.9 | 0.999 | 9.6 | 97.5 |
  | 22 | 268.2 | 0.516 | −49.4 | 26.4 |

  고도·방위는 기존 함수로 계산하므로 ±0.2° 안에서 같아야 한다. 차이가 크면 멈추고 보고한다.

## 2. 보기 `moon` ("달 보기")

- **조작**: 음력 날짜 슬라이더(1~29일, 키보드로 조작)를 둔다. 과제의 controls가 아니라 관찰 조작이며, 기존 시각 슬라이더와 같은 방식을 따른다.
- **우주에서 보기**(위에서 본 그림)
  - 왼쪽에 태양을 두고 햇빛 화살표를 그린다.
  - 가운데 지구를 두고, 그 둘레에 달 궤도와 날짜별 달 위치를 그린다.
  - 달은 언제나 태양 쪽 반이 밝다.
- **땅에서 보기**(저녁 7시 남쪽 하늘)
  - 서·남·동 지평선을 그리고, 달을 고도·방위에 그린다.
  - 밝은 부분과 어두운 부분은 frac과 waxing에 맞게 반달·초승 모양으로 그린다. 밝은 쪽이 오른쪽(서)인지 왼쪽(동)인지도 맞게 그린다.
  - 보이지 않으면 문구를 띄운다.
- **라벨**: "태양", "지구", "달", "서", "남", "동", "음력 {d}일"
- **모양 이름 표시**: 그림에 모양 이름을 쓰지 않는다. 학생이 관찰해서 고르는 것이 과제이기 때문이다. 기록을 마친 뒤에만 "이 날의 달: {이름}"을 보여 준다.
- **글자 크기**: SVG 글자는 390·1280 px 모두 13 px 이상이어야 한다(`svg-text.spec`가 검사한다). 다크 모드 대비도 맞춘다.

## 3. 과제(매니페스트 `tasks` 끝에 추가)

1. **moon-change**(view moon, answer moon-evening-change)
   - 질문: "여러 날 동안 저녁 7시에 같은 곳에서 달을 보면, 날이 지날수록 달의 모양과 위치는 어떻게 변할까?"
   - 선택지
     - waxes-east "점점 차오르고 동쪽으로 옮겨 가요"
     - wanes-west "점점 줄어들고 서쪽으로 옮겨 가요"
     - same "모양과 위치가 그대로예요"
2. **full-moon**(view moon, answer full-moon-day)
   - 질문: "보름달은 음력 며칠 무렵에 볼 수 있을까?"
   - 선택지: "3"(3일 무렵) / "8"(8일 무렵) / "15"(15일 무렵) / "22"(22일 무렵)
- 각 과제에 다섯 가지 when probe(before-observe, observing, record-mismatch, record-match, prediction-mismatch)를 모두 질문형으로 쓴다.
- **forbiddenAnswers 추가**: 활용형을 포함한다.
  - "점점 차올라", "차오르면서 동쪽"
  - "보름달은 음력 15일", "15일 무렵에 보름달"
  - "동쪽으로 옮겨 가", "달은 스스로 빛을 내지 않"
  - "햇빛을 받는 부분"
- **limits 추가**: 위상, 이각, 삭망월, 황도
- 전수 가드에서 probe와 화면 문구가 금지 구절에 걸리지 않아야 한다.
